# Hybrid paper-trading monitor

This feature converts explicit conditions in analysis reports into auditable execution plans and simulates trades locally. The post-close path uses complete daily bars only; the intraday path polls realtime quotes against the currently authoritative report's entry, stop, target, and quantifiable watch conditions. New reports take over under the market-session contract below instead of leaving stale entry plans authoritative indefinitely. It never connects to a broker, submits a live order, or changes manually recorded portfolio holdings.

## Enable it

### Watch versus conditional entry

`watch` grants no entry permission; an ideal price alone is not authorization. New reports can explicitly authorize a candidate with `action=buy/add` and `dashboard.phase_decision.entry_mode=conditional`, while `immediate_action` still says to wait for price/volume conditions. The optional `none` value means no entry authorization; `immediate` does not bypass execution checks. Historical reports without this field retain their existing semantics and are not rewritten.

Candidate authorization is separate from permission to fill. A first recommendation may start confirmation, but the backend independently enforces two-session confirmation, entry conditions, style/ATR geometry, net risk/reward, quote freshness, market and account limits. Scores must not be increased merely to produce a plan, and watch reports must not be promoted into buys.

Daily data must cover the requested latest completed session. Non-empty stale responses fall through to other providers; total failure is reported rather than mixing stale bars with fresh quotes as a complete current analysis. Inapplicable or missing capital-flow inputs are limitations, not automatic score/action/confidence penalties. Explicit fetch failure may lower confidence once. Genuine negative financial evidence, broken support and risk events still affect analysis.

## Trading style and execution-layer risk control

`PAPER_TRADING_STYLE` binds analysis and execution to one time horizon, so an LLM cannot mix a short-term target with a long-term stop in the same plan. `PAPER_TRADING_STYLE_OVERRIDES` is a JSON object keyed by exact `market:symbol`; unscoped bare symbols no longer match and legacy keys need a market prefix. Styles come from configuration and are never hard-coded by model. The effective profile is frozen into report context, DecisionSignal, execution plan, and position lot, so later configuration changes do not rewrite history. Opportunity-pool candidate analyses use the pool style frozen when the candidate was screened (`MARKET_OPPORTUNITY_STYLE`, or `PAPER_TRADING_STYLE` when empty) as their base style, and the resulting plans and lots freeze it; same-session reanalysis keeps the source plan's frozen style instead of reverting to the account base style. Watchlist and other analyses still use `PAPER_TRADING_STYLE` as the base style. See [Market opportunity pool](market-opportunity-pool_EN.md#limits).

Ordinary entry confirmation defaults to `2` adjacent actual trading sessions. Same-day repeats, holidays, unavailable calendars and metadata dates inconsistent with server report dates do not increment it. Weekend bullish reports are observation-only and do not freeze accepted entry authority. Fresh but non-executable new reports freeze unfilled entry; expired reports cannot seed confirmation. Each report's confirmation window ends at the next actual session close, and old candidates separated by intervening sessions cannot complete today's confirmation.

The market phase in which a report is produced is separate from its intended holding horizon. An intraday manual analysis still uses the frozen style default (`10d` for short swing, `swing` for position, and `long` for trend) instead of being treated as an intraday strategy merely because it ran during continuous trading. An explicitly supplied horizon must also be compatible with the style.

| Style | Complete daily-bar input | Core MAs | Expected / maximum holding sessions | Entry legs / add limit | Event-LLM cooldown / daily cap | Risk multiplier | No-material-change refresh |
| --- | ---: | --- | --- | ---: | --- | ---: | ---: |
| `short_swing` | 80 | 5/10/20 | 3–10 / 15 | 2 / 1 | 90 min / 2 | 0.75 | daily |
| `position` (default) | 180 | 10/20/60 | 10–40 / 60 | 2 / 1 | 240 min / 1 | 1.00 | every 2 sessions |
| `trend` | 500 | 20/60/120/250 | 40–120 / 180 | 3 / 2 | 1 session / 1 | 0.80 | every 5 sessions |

Quote polling and LLM cadence remain separate. Deterministic quote, stop, target, T+1, concentration, and account-risk checks keep using the configured polling interval; the LLM runs only for post-close refresh, material opening deviation, or an event that passes the profile cooldown and daily cap. Insufficient style history is recorded explicitly and blocks new risk instead of pretending that a shorter sample satisfies the profile.

Same-symbol exposure now uses two caps: `PAPER_TRADING_MAX_SYMBOL_EXPOSURE_PCT` remains the legacy global ceiling, and the effective ceiling is the stricter value between that global cap and `PAPER_TRADING_ASSET_EXPOSURE_CAPS`. Defaults are `20%` for individual stocks, `30%` for theme ETFs, `40%` for broad ETFs, and `20%` for unknown. Exposure still aggregates all open lots for the exact identity only; it does not merge all theme ETFs or all broad ETFs into a shared pool. If portfolio-level ETF bucket caps are needed later, they should be added as a separate rule and field set. Broad/theme ETF attribution only uses explicit `PAPER_TRADING_ASSET_CLASS_OVERRIDES` or existing trusted structured provider/context metadata, never LLM free text, report summaries, `raw_result` fields, or name heuristics; unidentified ETFs stay in the conservative unknown bucket. The current implementation exposes asset type, class cap, effective cap, and classification source in paper open/add gate evidence and paper `portfolio_context`; `portfolio_context.sizing_context` also includes cash, book equity, risk budget, plan capital ceiling, total exposure room, and asset exposure room so the model can understand capacity constraints, but it is read-only context and does not authorize a trade. Later R-slice prompt or UI wording should keep consuming those same fields once merged.

Paper fills no longer assume zero cost by default: slippage `0.03%`, commission `0.03%`, minimum commission `5`, and A-share stock sell-side stamp duty `0.05%`. Stamp duty applies only to stock sells; ETF/fund fills do not inherit it. Commission, minimum commission, and slippage are local account assumptions rather than a universal exchange or broker quote. Events and performance retain commission, tax, slippage, gross PnL, and net PnL separately; legacy fills retain their persisted totals and are not recomputed.

Before each monitor run, report-to-plan compensation scans recent stock-analysis reports for missing current-version paper plans and repairs them through the same `create_plan_for_report` contract. Immediate processing and scheduled repair share one durable state machine with bounded attempts and an explicit next-retry time. Terminal rows cannot repeatedly consume the scan batch, and the page exposes each report's classification, attempts, error, and final signal/plan. Market reviews never become execution plans, and old plans or filled lots are not deleted.

When report compensation is enabled, each compensation pass first runs `bootstrap_strategy_observations` idempotently: for identities whose latest report exists but no thesis has been recorded, it initializes an observation baseline with confirmation count `0`, no plan authorization, and no fill/position mutation. Re-running it does not create duplicate theses. A failed latest report or a latest report without a signal cannot fall back to an older successful report.

The market review is first persisted as a structured state with region, session, source report, freshness, and policy version. `normal` permits new risk at `1.00`; `cautious` still requires every symbol/account gate and scales new buys to `0.50`; `risk_off` blocks opens/adds; missing, stale, invalid, or unknown context is `unavailable` and fails closed. Absence of risk keywords cannot claim `normal`. Stops, targets, T+1 pending exits, reductions, and sells are never blocked by this new-risk gate.

The profile values are initial defaults for horizon and risk consistency, not a claim of proven persistent alpha. They are informed by SSE trading rules and fee conventions, multi-asset time-series-momentum evidence, volatility-managed exposure, the erosion of high-turnover signals by trading costs, and the sensitivity of China-equity momentum findings to samples and formation/holding windows. Evaluate model × style × market combinations with rolling out-of-sample periods instead of jointly tuning on the best historical interval. Sources:

## Execution contract

### Frozen horizon and entry setup

The medium-term `position` style accepts `10d` and `swing`. New plans use 10 and 40 holding sessions respectively. New `trend` plans with `long` use 120 sessions; incompatible `10d`/`swing` horizons cannot shorten them. Style-matching symbolic horizons consume the frozen style default, while compatible numeric horizons retain their explicit duration, capped by the style maximum. Existing frozen plans/lots, including legacy 20/60-session records, are not rewritten. Import repair preserves entry dates, quantity, and cost.

### Market and fundamental evidence quality

Historical and realtime volume use shares/units. Adapters convert lot-based providers; new cache source tags include `|vol=shares` to prevent double conversion. Legacy Efinance/Pytdx rows normalize on read. Unknown sources and ambiguous old AkShare rows cannot support volume comparisons and require the existing history-fetch path to refresh them. Post-close/non-trading quotes do not create or overwrite daily bars. Day-over-day comparisons require adjacent actual sessions. Style history requires unique valid dates and a valid latest close; opportunity screening also requires the full 80/180/500-session window.

Forecasts, preliminary earnings and actual financial reports use period-scoped calls and distinct meanings. Current summaries require attributable dates; stale, future or undated data cannot become current positive evidence. At most the latest two completed quarters are queried under the existing aggregation timeout. Provider timeout/missing data stays unavailable; absent forecasts do not imply absent risk. This does not claim point-in-time replay support for every fundamental source.

Prompts explicitly permit a supported buy recommendation for an empty account, separate medium/long-term thesis from short-term timing, and forbid treating missing news/fundamentals as safety evidence. These changes do not force buys or relax critical trade fields, T+1, capital limits or existing position protection.

After backup, operators can run `PaperTradingService.repair_portfolio_import_strategy_fields()` once to repair missing style fields on legacy imports. Repeated runs preserve complete historical frozen styles. This operation does not create trades or change cost, quantity, trade events, or original entry dates, and does not require users to synchronize holdings again.

Reports may declare `dashboard.battle_plan.setup.setup_type` as `breakout`, `pullback`, or `trend_continuation`. Legacy setup inference uses existing structured price rules, never summary prose. Intraday and EOD share the frozen contract: breakout requires breakout, volume, and momentum; pullback requires trend, frozen support, and contracting volume; continuation requires trend and momentum. A high aggregate score cannot replace a missing required factor. Intraday contraction uses provider volume ratio, never partial-day cumulative volume compared directly with full-day average volume.

Entry geometry checks minimum percentage stop distance, supplied ATR noise, and frozen support proximity. These are initial risk parameters, not return guarantees; small absolute price differences alone do not invalidate a medium-term setup.

- Scheduled/system reports and reports completed during premarket, lunch, the closing auction, or postmarket become eligible in the next trading session. A report may become same-session entry authority only when a manual Web/API/CLI/bot request completes during continuous trading and its frozen market session matches the still-open session at plan creation. Same-session authority does not bypass quote freshness, composite-factor, capital, or account-risk gates.
- Only whitelisted rules are executable: price ranges or limits, closing above a prior-data moving average, breaking a prior high, and volume relative to the average of prior sessions.
- When a report explicitly says “volume breakout” without a multiple, the policy applies a disclosed default: volume at least 1.5 times the average of the previous five complete sessions.
- Vague phrases such as “watch volume” remain audit context. They cannot trigger a fill and do not veto independently structured rules merely because they are not machine-decidable.
- Every executable condition on a plan must pass. Missing prices, missing volume, insufficient history, or ambiguity in an executable rule fails closed. Purely qualitative reminders are explicitly unavailable and never masquerade as passing factors.
- Report action checklists explain the model's reasoning and always remain audit context; they never become trading rules. Mandatory rules are parsed only from structured `watch_conditions` through the whitelist, so a display-oriented checklist cannot accidentally change the trading contract.
- Automatic entries also require the composite contract: valid stop and target, minimum reward/risk, at least two available and passing market-factor domains, and the market-factor weighted composite-score threshold. Market-factor domains cover volume, momentum, trend, and breakout. Report conviction is audit evidence only; it does not replace the market-factor count and does not contribute to the composite score.
- A price touch is only an entry gate, not a standalone buy signal. If price is reached but the broader factor evidence is weak, the plan records not-triggered or fail-closed and does not open.
- Rolling inputs exclude the current bar to prevent look-ahead leakage.
- Post-close entry uses the trigger day's close. Intraday entry uses the quote observed by the monitor. Stop, target, maximum holding sessions, and later reduce/sell/avoid signals may close a paper position.
- New reports may optionally emit versioned `entry_legs` for initial, pullback-add, or breakout-add entries, each with price rules, prerequisite legs, a plan-budget fraction, and maximum executions. Legacy “ideal + secondary buy” fields remain one entry range and are never guessed into two fills. The first fill freezes the full plan capital/risk budget; later lots share that snapshot and remain bounded by current cash and total exposure. Add-on lots for one symbol do not consume extra distinct-holding slots, but every lot keeps its own cost, execution timestamp, stop/target, and T+1 state. The account's holding count (`open_position_count`) is recounted from the distinct symbols of its open lots after every open and close instead of being incremented and decremented; each EOD run also first reconciles it against the actual lots, and `open_position_counts_repaired` in the run summary reports how many accounts were corrected.
- New reports may also emit versioned `exit_legs` with `first_take_profit`, `final_target`, each leg's `target_price`, and `allocation_fraction` for staged profit taking. Staged exits are enabled only when `exit_legs` is explicit; legacy single `take_profit` reports keep the original full-lot target behavior. The engine computes weighted target price and weighted reward/risk from every exit fraction, executes each target leg at most once, and keeps hard stops, model sells, defensive reductions, and T+1 protection active for all remaining quantity.
- The canonical field for each exit leg is `target_price`; exit legs must not reuse entry-leg `price_rules`. For already persisted reports generated by the previous underspecified prompt, a single bounded `close_between` range is normalized only when `first_take_profit` / `final_target` uniquely validates the target. Missing or contradictory targets remain fail-closed.
- When a report provides a valid, finitely bounded explicit `entry_legs` contract, stop/target geometry and minimum reward/risk are both calculated from the explicit entry prices; the broader ideal/secondary range no longer overrides either check. Missing, unbounded, or contradictory explicit legs remain fail-closed. Repeating plan creation may revalidate an existing plan only when that plan has never produced a paper fill; a state transition is persisted as plan audit evidence and creates no duplicate plan, trade, notification, or fund mutation.
- If a plan is rejected for `risk_reward_below_policy`, the system does not lower thresholds, silently edit model prices, or treat a near first target as the full target. It creates at most one `plan_contract_low_payoff` same-model reanalysis request for the same plan and trading session; until a replacement report is stored, the plan remains non-executable or reanalysis-blocked.
- Ordinary or unknown CN A-share instruments are treated as T+1 by default. If a stop/target breach happens on the buy day, the system records a `pending_exit` event, freezes sellable quantity, and closes on the next actual trading session using that session's fresh quote instead of the old stop or target price. A pending exit outranks later reports; otherwise the engine checks each lot's effective stop/target and same-model holding signals created after that lot was filled. Pre-entry signals cannot affect a new lot, and cached available quantity cannot bypass CN T+1. Only exact symbols listed in `PAPER_TRADING_T0_SYMBOLS` are treated as T+0.
- Reports select `position_actions.empty/holding` using frozen `holding_state`; an empty account never executes hold, reduce, or sell. Post-entry reports in the same model/market/symbol scope may propose versioned stop/target revisions. Continuity adjudication, validated fresh quotes (or the latest completed session close for postmarket), and frozen style/structure/volatility guards determine application. Missing valid prices defer retry without changing protection or consuming a terminal revision key; contradictory prices are rejected. Long stops may only tighten. `hold/watch` cannot silently exit by moving a target below the reference price or a stop above it. Only accepted revisions update lots; unified thesis prices sync only when all open lots in scope agree, otherwise per-lot evidence is retained. Repeated handling is idempotent. Explicit sell/reduce and existing T+1 pending exits retain independent priority and never wait for the LLM.
- Multiple open lots for the same model, account, market, symbol, and currency are resolved as one aggregate holding for model reduce/sell signals. One aggregate resolution creates one `resolution_key` and one logical simulated order; fees and minimum commission are calculated once and then FIFO-allocated to lot events. After the same defensive signal is consumed, later polling buckets cannot apply it again. Reduce quantity is floored to the executable lot size; if it rounds to zero, the monitor records a `suppressed` audit observation rather than turning the reduce into a full close.
- CN paper fills never occur before 09:30. From `09:30–09:35`, the system uses the project's configured realtime providers to obtain a fresh, attributable opening quote and confirm entry plans produced in the prior session; Tushare `stk_auction` permission is not required. This quote is not auction order-book, matched-volume, or imbalance data, and the system does not claim otherwise. Exact symbol/market/source identity, price, provider timestamp, and fetch timestamp are mandatory; missing, stale, or mismatched evidence fails closed. Being above the planned entry range or having poor spot reward/risk alone does not request reanalysis. Planned economics are recomputed from the entry-range midpoint, stop and weighted exit target, not a cached ratio. A material downward entry-band break, a reached stop/first exit target, abnormal prior-close gap/volume ratio, or invalid planned reward/risk creates one durable same-model reanalysis request and blocks new open/add until the replacement report is stored. The confirmation sweep never fills by itself. When no material deviation exists, the existing multifactor, capital, and account-risk gates remain the sole entry executor. Existing stops, targets, T+1 handling, reductions, and exits never wait for the LLM.
- Every model and source report has a separate plan and ledger. Re-running a trading date cannot duplicate fills or events.
- A stock report freezes its execution purpose in the same transaction as its first save (`analysis_report_execution_intents`): `paper_candidate` may back paper trading, `research_only` is research evidence only. The row also freezes the execution scope (`primary` or `experiment:<id>:<a|b|c>`), `decision_as_of`, policy version, and source. The purpose comes only from trusted server-side task context. An invalid purpose fails the whole report save, and the application rejects later rewrites. Same-named fields in model output, API request bodies, or external data cannot grant permission. Only `paper_candidate` reports whose scope equals the service instance scope (`primary` by default) may drive manual plan creation, immediate post-save compensation, scheduled compensation, thesis bootstrap, holding-defense signals, latest-report selection, sector/asset metadata, and account context. `research_only` reports receive no portfolio or paper-position context and never create a DecisionSignal; scheduled compensation records them as terminal `execution_not_authorized`. Consumers filter before choosing the latest report, so a newer research report cannot mask a valid older report that still protects a holding. Rejection reasons are fixed: `research_only`, `execution_scope_mismatch`, `execution_intent_missing`, or `execution_intent_unknown`.
- Opportunity-pool red-light research can be executed comparatively across three isolated experiment arms (A/B/C) that share one research result but persist independently. A trusted orchestrator rebuilds the shared evidence into an arm-local executable report through `import_research_bundle(bundle, *, experiment_id, arm)`: it verifies the bundle version, recomputes `bundle_id`, and checks the full research payload against `output_hash`, then persists a `paper_candidate` report bound to scope `experiment:<id>:<arm>` and derives that arm's decision signal. A correct hash is an integrity check, not execution authorization; import is idempotent (re-importing the same evidence hits the same record), the original research report and intent are never mutated, and the same evidence entering three arms is never reused across them — each arm authorizes only its own scope. The API cannot upload an arbitrary scope to make a report executable. The experiment registry stores only the **name of the environment variable** holding each arm's database URL, never the URL; before start it verifies the three arm databases are mutually distinct and none equals the main database, and audit output hides passwords. The worker `scripts/run_opportunity_experiment.py` binds the arm `DATABASE_URL` before importing `src`, disables ordinary trade notifications, consumes no main-account task, and performs no position sync.
- For experiment scopes the market-regime risk control collapses to a **single decision point** in the paper engine: A/B/C scopes obtain one authorization-and-scaling verdict from `evaluate_opportunity_market_policy`, read jointly by position sizing, the per-symbol exposure ceiling, the total-exposure pre-check, and the account risk gate, and the market multiplier is applied exactly once per budget constraint. Under a red-light (`risk_off`) regime with an intact medium-term trend, arm A keeps the existing regime control and opens nothing, arm B fills a small lot under the red-light trial scaling (0.25×, 5% per symbol, 20% total of the frozen baseline), and arm C ignores direction and fills at the full budget; an already-open position above the trial cap is held, never force-sold. The main account and green/yellow-light behavior keep their existing regime semantics.
- The paper-trading page offers **read-only cross-arm comparison on the same page**: a top "execution scope" dropdown fed by `GET /api/v1/paper-trading/scopes`, where `primary` reads the main database and `experiment:<id>:<arm>` reads that arm's isolated database. Selecting an experiment arm makes the plan/position/operation/event/account lists carry `scope_id` against that arm's read-only connection, shows a read-only banner, and disables write actions (monitor runs, account creation, fund adjustments, manual risk control, portfolio sync); switching back to the primary account restores them. Scopes are resolved only through the server-side trusted registry (`OPPORTUNITY_EXPERIMENT_REGISTRY_PATH`) into read-only connections — the client cannot pass a database address — and a missing registry or invalid scope fails closed (404) rather than falling back to the main account; neither the endpoint nor the dropdown ever exposes a database address or credential.
- An LLM report is new evidence, not automatic execution authority. The system keeps one effective strategy thesis for each source model, exact market, canonical symbol, and frozen trading style, plus an immutable transition audit for every adjudicated report. The page shows the raw LLM action, effective execution action, entry permission, confirmation progress, and reason separately; legacy data without this audit is explicitly marked not recorded instead of being inferred by the client.
- Both the standard and Agent analysis paths receive the effective thesis and pending transition for the same model, market, and exact symbol as read-only context. The model must still evaluate current evidence independently and must not repeat a historical conclusion merely to satisfy a confirmation count. Missing continuity context never blocks report generation and adds no new required Tool Schema output field.
- For the medium-term `position` style, an ordinary directional reversal requires confirmation on `2` distinct trading sessions by default; repeated analyses on one day count once. The first contradictory observation immediately freezes remaining open/add authority on older plans but never deletes filled lots. A same-model material intraday reanalysis verified through the opening/event workflow may take authority immediately. Out-of-order reports cannot reclaim authority, and model, market, symbol, or style scopes never mix. Same-posture or holding-aware `hold/watch` evidence may refresh tactical risk, but a stop may only tighten and an unconfirmed reversal cannot loosen protection, arbitrarily replace targets, or trigger a model-only exit.
- Strategy continuity governs LLM-driven entry, add, and ordinary direction changes only. It never delays deterministic price stops, targets, T+1 pending exits, account hard-risk controls, or market-regime hard gates. The mechanism is intended to reduce random opinion churn and improve auditability; it is not evidence of improved returns, and confirmation/profile parameters still require forward observation and rolling out-of-sample calibration by model and market.
- The Web UI uses `/api/v1/paper-trading/operations` for derived runtime state instead of treating raw `plan.status` as monitor state. A triggered plan with open or T+1-pending lots remains visible as position monitoring or pending exit; only terminal plans with no live lots leave the current-operations view. Every plan remains in a separate audit view and is never deleted merely to shorten the page.
- The Web page is ordered for human review first and opens only four core cards, answering in turn how the money stands, why (or what) traded, what is held, and what is planned. **Account overview** has one row per currency and never sums across currencies; with complete valuation it shows equity at market, return vs. initial capital, cash, position value, position ratio, and realized / unrealized PnL, while unpriced holdings make equity fall back to cost basis and show market-based numbers as "—". Session PnL and drawdown come only from the latest account risk snapshot, labelled with its date, and show "—" when the snapshot is missing, several model accounts share the currency, or an experiment scope is selected. **Why no trade** (titled **Trading facts** once a lot was opened on the latest plan date) only restates the latest plan date's plan count, buy and executable counts, counted reasons why buys are not executable, the market gate, current account risk locks, the open-lot count, and lots opened on that plan date, without inferring causes beyond the data; experiment scopes do not read primary-DB risk locks or the market gate. **Open lots** lists source / trading style, quantity, cost, price, unrealized PnL, stop, target, and held / max sessions, with recently closed lots collapsed by default showing only open/close prices, close reason, and realized PnL, never a live mark. **Plans** shows only buy-like plans of the latest plan date with their executable state and reasons by default, switchable to every plan of that date. Recent audit events follow; risk-lock and risk-snapshot detail, manual hold / resume, risk events, fund adjustments and journal, side-by-side model performance, runtime heartbeats, opening confirmation, report-to-plan processing evidence, frozen strategy snapshots, intent resolution, risk revisions, notification dispatches, rule evidence, summary stats, aggregate holdings, the operational lifecycle, and lot details all remain available inside four groups collapsed by default: Risk detail, Funds and model performance, Runtime diagnostics, and Plan and lot detail.
- The top cards load their own data and do not follow the audit tables' pagination: capital accounts, open lots, and aggregate-holding marks each read the API's single-page cap of `500` rows, plans read the latest `100`, closed lots the latest `20`, and risk snapshots and locks their first page. The cards warn when open lots exceed the cap or the latest plan date may be cut off. Backend codes in the cards and in some audit columns (actions, non-executable reasons, risk-lock states and reasons, close reasons, source kinds, trading styles, event types, and similar) are translated into Chinese / English text; unknown codes are shown verbatim and missing values as "Not recorded" or "—".

## Intraday polling boundaries

Intraday polling runs only during the regular market session. Missing quotes or quotes older than `360` seconds fail closed. This permits one five-minute polling interval plus limited clock/network tolerance without reusing a price across two polling cycles. Realtime quotes come from the existing `DataFetcherManager.get_realtime_quote()` route, and observations record source, provider timestamp, fetched timestamp, price, volume ratio, and change evidence. Every quote for an open holding that passes exact-symbol and freshness validation is persisted idempotently by `model + market + symbol + polling bucket` as a non-fill valuation mark, even when no stop, target, risk, or trade event occurs. The monitor refreshes every holding before evaluating any new entry or add-on, preventing traversal order from creating a false stale-valuation lock. Volume confirmation uses provider `volume_ratio`; when it is unavailable, that factor is marked unavailable instead of treating incomplete cumulative volume as a breakout confirmation.

Daily analysis runs in an independent single-flight worker thread. Slow market-data, news-search, or LLM calls therefore do not block intraday paper-trading polling. If the previous daily analysis is still running, a duplicate trigger is skipped and logged. While visible, the paper-trading page refreshes silently every 60 seconds and synchronizes immediately when brought back to the foreground.

The scheduler wakes every minute, then evaluates the phase in each plan's own market and timezone; closed markets and pre-09:30 phases do not fetch ordinary realtime quotes or write opening-confirmation observations. For A-shares, an independent `09:30–09:35` Asia/Shanghai confirmation task catches up immediately when the process starts inside the window and retries at most every 30 seconds. Each symbol uses one quote per sweep; confirmed plans are not reconfirmed, and material-deviation reanalysis is deduplicated by plan, model, and session. The confirmation task only records evidence or requests reanalysis. Continuous-session monitoring remains the sole paper-fill executor at its configured interval during `09:30–11:30` and `13:00–14:57`; the `14:57–15:00` closing auction is skipped for fills. If process timing misses the dedicated sweep, the first continuous-session evaluation applies the same fail-closed opening confirmation before evaluating an old plan. A model-authored `next_check_time` becomes a once-only reanalysis obligation only when it is a timezone-qualified ISO datetime, or an exact `HH:MM` (optionally “next session”) inside a supported session; vague prose, placeholders, stale targets, and closed-session times remain descriptive. The Web page renders observation, provider, and fetch timestamps in China time (`UTC+8`), while the database keeps UTC for cross-market auditability.

CLI schedule mode and the Web runtime scheduler now consume the same task-window contract. Every intraday cycle logs completion, duration, closed-market skips, and fail-closed totals even when it creates no fill or new observation, so “no condition matched” is distinguishable from “the scheduler did not run.”

In split Web/API and analyzer deployments, scheduler truth comes from the shared database rather than the Web process's local memory or the most recent quote observation. Daily analysis, the 09:30 opening confirmation, and intraday monitoring publish separate task-level heartbeats containing owner, enabled/running state, interval or window, last wake/start/finish/success/error/skip, and next due time. An `idle` heartbeat is published before a task's first execution. The page identifies stale or dead owners explicitly, while the shared lease prevents two containers from executing the same time bucket.

Auction-deviation and `next_check_time` reanalysis requests are persisted before a conditional database update atomically assigns one submitter. After restart, reconciliation first looks for an existing matching report by task/query, model, and exact symbol instead of blindly resubmitting. Ambiguous external calls fail closed after the recovery window. Such a request blocks new entry only; existing-position exits remain live.

The intraday path is still paper-only. It does not call broker APIs, create live orders, or mutate manually entered portfolio holdings.

Intraday observations are persisted by polling bucket for auditability. This version does not prune observation rows automatically; if you run minute-level polling for many stocks and models over a long period, archive the database periodically or add a retention setting in a later change.

## Analysis frequency and strategy horizon

Quote polling and full LLM analysis are separate frequencies. The default five-minute quote poll executes deterministic price, stop, target, volume, and account-risk rules and does not call an LLM every five minutes. The default is the `position` profile, not intraday high-frequency trading: ordinary CN shares are T+1, fills are quote-based simulations, and there is no order-book queue or broker confirmation. Complete post-close analysis remains the primary anchor; 09:30–09:35 is opening confirmation, and only a material deviation or a profile-eligible event within cooldown/daily-cap limits requests same-model reanalysis.

The versioned table above is the implemented contract rather than a loose range. Input design is not merely “more bars”: short swing emphasizes recent price-volume and 5/10/20 moving averages, while trend uses longer daily history and 20/60/120/250 moving averages. Every profile freezes the data cutoff, excludes incomplete bars, and preserves news-time causality. Evaluate profiles as whole contracts; do not tune only one threshold or increase call frequency and then claim strategy effectiveness.

## Capital and performance convention

Each `model + market + currency` owns an isolated simulated capital account. New position size is the minimum allowed by stop-risk budget, plan-level capital cap, total account exposure cap, available cash, and market lot size (CN A-shares use 100-share lots). A staged plan freezes its capital/risk budget at the first fill; all legs share the declared fractions of that snapshot, so later deposits or equity changes cannot expand the original plan. Opening debits cash and increases exposure; closing releases exposure, credits cash, and realizes PnL.

The Web “Paper fund management” area can explicitly initialize an account for a configured model and server-supported market before the first fill, then record deposits or withdrawals on existing accounts. The model and market lists come from `/api/v1/analysis/models`, so the page does not hard-code a fixed pair of models or a fixed market subset. Every adjustment requires a positive amount, a reason, and a client idempotency key, and stores cash and book-equity snapshots before and after the mutation. Retrying the same payload with the same key returns the original journal row without applying it again; reusing a key for a different payload returns a conflict. A withdrawal is rejected atomically when it exceeds available cash or would leave existing exposure above the account's total-exposure limit.

“Book equity” is `available cash + invested cost`. It is a paper cost-basis measure and excludes unrealized PnL. `realized_pnl` remains closed-fill PnL only; account lists and performance metrics additionally derive `market_value`, `unrealized_pnl`, `total_pnl = realized_pnl + unrealized_pnl`, and `market_equity = cash + market_value`; if any open lot is unpriced, `valuation_complete=false` is returned so missing marks are not counted as zero. After a partial exit, the lot keeps remaining quantity, remaining cost, sellable/frozen quantity, realized quantity, fees, and realized PnL; the Web lot table shows those fields separately so one realized loss is not mistaken for the whole holding's total PnL. Funding adjustments change only cash and external net cash flow; they never rewrite position quantity, position cost, exposure, realized PnL, or trade history. Subsequent risk, position, same-symbol, and total-exposure caps use the adjusted book equity. `initial_capital` remains the account's creation-time starting amount for audit.

Valuation is display and model-context data only; it never relaxes the 360-second fresh-quote gate used by execution. Valuation prefers the latest reliable same-model observation for the exact symbol, and falls back to the latest complete daily close when no observation is available. Observation and daily-close candidates are compared by their actual timestamps, so a newer complete close may override an older intraday observation. A normal-poll `valuation_mark` always has `action=none`; it is used only for holding display, model context, and account-risk calculation, and is neither a fill nor an entry signal or substitute execution quote. Quotes older than 360 seconds and daily closes are still usable for valuation, but are flagged with `mark_stale=true` / `valuation_stale=true` and are never treated as fresh execution quotes. If any open lot has no mark, account-level `market_value`, `unrealized_pnl`, `total_pnl`, and `market_equity` return `null` with `valuation_complete=false`; `priced_market_value` is only the partial value for priced lots. `unpriced_position_count` counts unpriced lots, while `unpriced_holding_count` counts grouped symbol identities.

The account remains paper-only. It estimates configured slippage, minimum commission, and sell-side stamp-duty/tax so local reviews include realistic cost assumptions, but it still does not model price-limit queues, order-book matching, execution priority, or broker confirmations. Legacy fixed-notional positions remain readable and are not destructively rewritten.

## Account-level risk control

Each simulated capital account now records persistent risk snapshots keyed by trading session and polling bucket. A snapshot is computed from complete marked-to-market equity and records cash, exposure, realized/unrealized/total PnL, daily loss, drawdown, losing logical-exit streak, daily trade counts, daily open/add counts, valuation completeness/staleness, and total/symbol/sector-or-asset/correlation/unknown utilization. External deposits and withdrawals adjust the session-start equity; they do not manufacture profit or erase drawdown.

Every new open/add path passes an account-risk gate inside the same ledger transaction. Defaults are 3% daily loss, 10% drawdown, 8% drawdown recovery threshold, 3 losing logical exits, 10 daily trades, 5 daily open/add orders, 60% sector or asset-group cap, 60% correlation-cluster cap, and 50% unknown-bucket cap. A hard breach, nonpositive equity, missing/stale valuation, cooldown, manual hold, or count limit rejects only new risk. Reductions, closes, stops, targets, and T+1 pending exits remain allowed subject to ordinary quote and sellability checks.

Sector or asset-group evidence uses only persisted attributable report/context metadata. Missing metadata, insufficient complete bars, or insufficient correlation overlap goes into the explicit `unknown` bucket and applies the conservative unknown cap. Correlation clusters use 60 complete daily sessions, at least 30 overlapping return samples, and a 0.85 threshold; unavailable data does not silently pass.

Risk-state transitions are immutable events. Manual hold/resume require a reason and idempotency key; identical retries return the existing event and conflicting key reuse returns a conflict. Manual resume cannot override unrecovered hard metrics. When Feishu is enabled, risk suspension/resume/reduce-only/cooldown entry-block events are sent through the existing channel once; notification failure only updates the risk event's notification state and never rolls back risk or trade ledger state.

## Position sync and analysis context

Portfolio management and paper trading remain separate ledgers, but explicit two-way synchronization is available:

- The portfolio page can import one current cached holding into one selected model or all configured model ledgers. The import requires an existing model report for the same exact symbol, enough paper cash, and no open paper position for that model and symbol. Failure leaves the whole transaction unwritten.
- The paper-trading page can record one confirmed paper-position execution into a selected portfolio account, with editable side, quantity, price, date, and fee. This writes only the local portfolio trade ledger and never connects to a broker.
- Both directions use idempotency keys plus persistent `paper_sync_links`. Retrying the same payload with the same key returns the original link; reusing a key for different data or syncing the same position side twice returns a conflict.
- A-share identity is market-qualified and exchange-qualified (`SH/SZ/BJ + six digits`); a bare numeric code is not treated as cross-market equivalent.

During scheduled analysis, ordinary manual analysis, and system-triggered same-model reanalysis, the pipeline reads all open paper lots for the current model and stock whenever no genuine explicit portfolio holding was supplied; reanalysis control metadata no longer shadows the paper holding. It aggregates by model, market, canonical symbol, and currency and injects that as the holding context. The frozen context includes total quantity, weighted cost, total cost, lot count, available/frozen quantity, stop/target lot summaries, cash, book equity, total exposure, symbol cost concentration, and valuation state so the model can judge add/hold/reduce. Same-symbol concentration is both model input and a hard paper-account cap for new/add buys: add-ons remain allowed inside the cap, but above the shared cap the service resizes to remaining capacity or rejects the new buy when it cannot satisfy the minimum lot size. This cap never blocks existing-position stops, targets, T+1 pending exits, or defensive reductions/sells. Actual opens remain bounded by cash, risk-per-trade, staged-plan capital, same-symbol cap, total exposure, and max-open-holding rules. Manual portfolio-page analysis context remains authoritative for that request, and one model's paper holding never leaks into another model's run.

When `PAPER_TRADING_FEISHU_NOTIFY=true`, paper open, T+1 pending-exit, and close events commit to the local ledger first, then create/send Feishu dispatches. Before calling the external webhook, the service atomically claims an eligible dispatch as `sending` in the database and commits it; only the caller that wins the claim sends externally. Send failures only update retryable `failed` state and never roll back the simulated fill; missing Feishu routing is recorded as `unconfigured`. Every paper monitor run retries pending/failed dispatches after ledger transactions finish; pending rows are prioritized and failed rows retry up to 3 attempts by default, avoiding endless outage spam or starvation of new notifications. `sending` means the process may have crashed after an external call; because the webhook has no idempotency key, this state is not retried automatically and should be audited manually.

Feishu lifecycle notifications include the model, exact symbol, simulated quantity and price, stop/target, post-event cash and exposure, trigger evidence, sync status or follow-up route. Close notifications also include entry/exit price, PnL, and return details. Validation does not send live Feishu messages.

## API

- `GET /api/v1/paper-trading/status` exposes monitor switches, scheduler state, thresholds, capital policy, Feishu readiness, and latest observation bucket.
- `POST /api/v1/paper-trading/plans` creates or reads an idempotent plan from one historical report. When the report's frozen purpose does not authorize the current paper account, it returns `409` with `error=execution_not_authorized`, `detail.reason` set to one of the rejection reasons above, and `detail.report_id`; the request body cannot override purpose or scope.
- `GET /api/v1/paper-trading/plans`
- `GET /api/v1/paper-trading/operations` returns one paginated runtime row per plan with pending/filled legs, open/T+1-pending lot counts, next-check and reanalysis state, persisted-transition-derived raw/effective actions, entry permission, confirmation progress and reason, and per-lot source-plan/effective stop-target values plus revision provenance. Each row and each open lot also carries `source_kind`, and each open lot carries `held_sessions` (same meaning as in the positions API).
- `GET /api/v1/paper-trading/positions` returns lots newest-created first, optionally filtered with `status=open|closed` (`limit` at most `500`). Each lot includes immutable source-plan stop/target, current effective values, and its latest versioned risk revision, plus two additive read-only fields: `source_kind` is the kind of the source report (`market_opportunity` for opportunity-pool, opportunity research, or experiment-import reports, `legacy` for the legacy baseline, `analysis` for any other report with a recorded execution intent, and `null` when the source report has no execution-intent row); `held_sessions` counts exchange sessions after `opened_on` up to the market-local today (open lots) or `closed_on` (closed lots), on the same basis as the end-of-day time exit, so reaching the lot's max holding sessions means the time exit fires at that session's close; it is `null` when the market calendar is unavailable and is never replaced by natural days.
- `GET /api/v1/paper-trading/holdings?model=&page=&limit=` aggregates open lots server-side by `source_model + market + stock_code + currency`, returning total, available/frozen quantity, weighted average cost, total cost, lot count, market value, mark source, stale flag, valuation completeness, and unrealized PnL. Per-lot audit remains available through positions/events.
- `GET /api/v1/paper-trading/events` distinguishes requested/executed/unfilled quantity, fees, logical order key, resolution key, quote timestamps, and `fill_evidence_grade`. `quote_based_unverified` means the fill is simulated from quote data only, with no order-book queue or real fillability proof. Each event includes its own `notification_dispatch` snapshot; close events and other non-notified events return `null`.
- `GET /api/v1/paper-trading/resolutions` returns intent-resolution audit rows with candidate/chosen/suppressed intents, policy version, resolution/order keys, requested/executed/unfilled quantity, and evidence.
- `GET /api/v1/paper-trading/risk-revisions` returns old/new/applied stop/target, applied/rejected/noop results, and evidence. A proposed line already beyond the reference price is rejected. A valid revision breached by subsequent fresh quotes is handled by the existing exit workflow.
- `GET /api/v1/paper-trading/auction-observations` retains its path for client compatibility and returns new `opening_confirmation` observations plus historical `preopen_auction` audit rows with distinct labels.
- `GET /api/v1/paper-trading/reanalysis-requests` returns paginated opening-confirmation-deviation or `next_check_time` reanalysis requests with source-plan, replacement-report/plan, lifecycle, and evidence.
- `GET /api/v1/paper-trading/report-plan-reconciliations` returns paginated durable report-to-DecisionSignal/paper-plan repair state with classification, attempts, next retry, error, and final signal/plan.
- `GET /api/v1/paper-trading/risk-snapshots` returns paginated account risk snapshots with valuation, state, permissions, concentration, and threshold evidence.
- `GET /api/v1/paper-trading/account-risk/locks` returns each account's latest risk lock and permissions, including whether new open/add is disabled while exits/stops/T+1 remain enabled.
- `GET /api/v1/paper-trading/risk-events` returns immutable account-risk events with old/new state, reasons, recovery conditions, linked resolution, and notification state.
- `POST /api/v1/paper-trading/risk/manual-hold` idempotently pauses new open/add for one paper capital account.
- `POST /api/v1/paper-trading/risk/manual-resume` idempotently requests account recovery; unrecovered hard metrics return a conflict.
- `GET /api/v1/paper-trading/accounts`
- `POST /api/v1/paper-trading/accounts` explicitly initializes an account for a configured model and market; an existing account is returned without resetting it.
- `POST /api/v1/paper-trading/accounts/{account_id}/adjustments` idempotently records a `deposit` or `withdrawal`.
- `GET /api/v1/paper-trading/adjustments` returns paginated immutable funding history, filterable by model, account, and type.
- `POST /api/v1/paper-trading/sync/from-portfolio` explicitly imports a cached portfolio position into one or more configured model paper ledgers.
- `POST /api/v1/paper-trading/sync/to-portfolio` explicitly records a confirmed paper-position execution into a selected portfolio account.
- `GET /api/v1/paper-trading/dispatches`
- `GET /api/v1/paper-trading/evaluations`
- `GET /api/v1/paper-trading/observations`
- `GET /api/v1/paper-trading/performance` summarizes by model and separates gross/net realized PnL, unrealized PnL, total PnL, valuation completeness, and unpriced-lot counts; model filters and totals are computed from the service/database result, not from the current Web page.
- `POST /api/v1/paper-trading/run` for a post-close daily-bar sweep; send `{"mode":"intraday"}` for a manual intraday observation sweep

All endpoints require an administrator session when administrator authentication is enabled.

## Fill quantities and capital limits

- Repeated reductions use the exact requested share quantity rather than applying a remaining-position fraction to the original quantity again. A multi-lot aggregate exit must keep cash, positions, and events consistent: any allocation failure rolls back the whole fill mutation, leaves the signal unconsumed, and records failure evidence for a later observation to retry. A durable T+1 pending-exit obligation is not a same-day sale.
- Both intraday and end-of-day entries reserve slippage and commission before lot-size rounding. Actual fill debit is checked against available cash, per-entry capacity, symbol concentration, and total account exposure. An unaffordable fill is rejected without overdrawing paper cash.
- `non_cn_t0` permits same-day paper exits for non-CN instruments. CN remains T+1 except explicit configured T+0 instruments. Internal paper rules do not replace the real market, account, and product rules.
- `quote_based_unverified` still means a quote-based simulation, not verified order-book liquidity, queue priority, or broker execution. This fix does not remove that limitation.

## Relationship to the 14-day backtest

This feature does not alter the existing backtest. The backtest still evaluates reports after `BACKTEST_MIN_AGE_DAYS` over a fixed window; paper trading evaluates report conditions after the report, using complete daily bars post-close and optional realtime quote polling intraday. Both metrics remain available and serve different purposes.

The status API exposes `intraday_monitor_last_run_summary` and `scheduler_last_run_summaries`: last actual completion, duration, target identities, quote fetch counts, and skipped/failed counts. A fetched quote still needs independent freshness and risk validation before a fill. A not-due callback preserves the last actual summary. The Web UI separates scheduler heartbeat time, actual run completion and observation bucket time; no targets or closed markets do not create artificial observations. Unknown summaries stay unknown, not zero. Lazy historical signal backfill cannot promote missing or ambiguous confidence to medium and authorize an actionable signal.

## Rollback

Set `PAPER_TRADING_INTRADAY_ENABLED=false` to stop only intraday polling, `PAPER_TRADING_PLAN_COMPENSATION_ENABLED=false` to stop report-to-plan repair, or `PAPER_TRADING_MARKET_CONTEXT_RISK_CONTROL_ENABLED=false` to roll back the market-context execution gate. Set `PAPER_TRADING_ENABLED=false` to stop all paper-trading monitoring. To roll back only the report-as-evidence strategy-continuity gate, set `PAPER_TRADING_STRATEGY_THESIS_ENABLED=false`; this restores legacy per-report authority without deleting thesis/transition audit rows or disabling deterministic stops, targets, T+1, and account-risk controls. The default profile can be restored with `PAPER_TRADING_STYLE=position`, but a style already frozen into a historical report, plan, or lot is never rewritten retroactively. Existing plans, observations, evaluations, funding adjustments, and paper ledgers remain for audit. Disabling it does not affect report generation or the original backtest. Correct a mistaken adjustment with a new opposite journal entry and an explanatory reason; do not delete or overwrite the original row.

Report execution purpose has no separate switch. On the first startup after upgrade, one transaction registers every existing non-market-review report as `paper_candidate/primary` (source `legacy_baseline`) and writes a baseline marker; restarts never repeat it, and historical plans, fills, and funds are not rewritten. Any report saved after the baseline without a purpose row, such as one saved by an old-version process during a rolling upgrade, is rejected with `execution_intent_missing`, so upgrade the Web/API and analyzer processes together. After rolling back to a version that does not know the table, the table and rows remain but are ignored, and the old version treats research reports as ordinary reports; only research reports already recorded as terminal by scheduled compensation stay out of the old compensation scan. Before rolling back, stop research report producers (for opportunity-pool red-light research, set `MARKET_OPPORTUNITY_RESEARCH_DAILY_LLM_BUDGET=0` or switch the opportunity mode to `observe`/`off`); while rolled back, set `PAPER_TRADING_PLAN_COMPENSATION_ENABLED=false` and do not create plans manually from research reports.
