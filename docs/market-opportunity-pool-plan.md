# 大盘风口机会池实施计划

> 状态：主体实现与离线联动验证已完成；真实 AKShare 数据源、独立验收及 3 个 observe 交易日尚未通过，未放行 paper  
> 计划编号：`market-opportunity-pool-20260831`  
> 风险等级：高风险（金融决策、自动 LLM 调用、模拟交易计划）

## 1. 目标

把现有“大盘复盘只影响个股判断和模拟交易风控”的能力扩展为一条可审计、可限额、可回滚的自动发现链路：

```text
完整盘后大盘报告
  -> 结构化风口主题
  -> 可信板块成分股
  -> 确定性过滤与评分
  -> 有时效的风口机会池
  -> 所有实际配置模型分别分析
  -> 历史报告 / DecisionSignal
  -> 现有报告到计划补偿
  -> 下一交易时段开盘确认和模拟监控
```

最终结果不是“LLM 从大盘文字里猜股票”，而是让数据层先产生可复核候选，LLM 只分析有限候选；已有模拟资金、T+1、止损止盈、大盘门禁和账户风险控制继续作为执行层权威。

## 2. 明确不做的事情

- 不连接券商，不提交真实订单。
- 不让 LLM 自由编造股票代码或板块成分股。
- 不把机会股自动写入永久自选；机会池与用户自选分离。
- 不按模型名写死 DeepSeek、Claude 或任何未来模型。
- 不在每次 5 分钟行情轮询时重新发现全市场机会，也不每 5 分钟调用 LLM。
- 不用今天看到的板块成分回填历史并宣称完成了无偏历史回测；历史成分存在幸存者偏差。
- 不复制 GPL 项目的实现代码；只借鉴公开架构思想。
- 不削弱现有报告动作契约、计划收益风险比、账户风控、T+1、行情新鲜度或 fail-closed 规则。

## 3. 当前代码基线

### 3.1 已经具备

- `DailyMarketContextService` 会从大盘报告生成并保存 `DailyMarketRegime`。
- 个股分析会消费大盘摘要和 `market_structure_context`。
- 大盘谨慎时会软化激进买入；执行层 `cautious` 缩小新增风险，`risk_off/unavailable` 禁止开仓和加仓。
- `MarketHotspotService` 已能产生领先行业、领先概念、落后主题和基础数据质量。
- `AnalysisHistory -> DecisionSignal -> PaperExecutionPlan` 已有持久补偿和幂等处理。
- 模拟交易已有开盘确认、盘中多因子、资金分配、集中度、T+1、退出监控和飞书成交通知。
- `alphasift_service.py` 内已有东方财富板块成分抓取和规范化思路，但 DSA 原生热点服务当前明确不依赖 AlphaSift。

### 3.2 缺口

- `MarketHotspotService.get_hotspot_detail()` 仍明确缺少 `hotspot_constituents` 和 `leader_stocks`。
- 当前数据路由主要支持“股票 -> 所属板块”，没有正式的“板块 -> 精确成分股”公共契约。
- 没有持久的风口运行、主题快照、候选股票、拒绝原因和模型分析任务账本。
- 没有将机会候选加入现有多模型分析批次的调度消费者。
- 没有机会来源维度的表现评估，无法区分“选股有效”还是“LLM/计划有效”。

## 4. 外部实现调研与复用决定

### 4.1 AKShare：直接复用数据能力

项目已经依赖 AKShare。首版成分股能力使用：

- `stock_board_concept_cons_em`：概念板块成分股；
- `stock_board_industry_cons_em`：行业板块成分股；
- 对应板块历史接口：用于 3/5 日持续性，而不是只看当日涨幅。

实现必须通过项目数据层适配，不能在业务服务中散落新的东方财富 HTTP 请求。网络失败、字段漂移或股票身份不完整时，候选发现 fail-closed。缓存只减少重复请求，陈旧缓存不能用于自动生成新风险。

### 4.2 Freqtrade：只借鉴“动态池 + 过滤链”

借鉴其 Pairlist 的生产者、顺序过滤、黑名单、活跃性校验、数量上限和刷新周期设计。由于其许可证为 GPLv3，本项目不复制源码；只实现符合本项目数据结构的独立过滤链。

### 4.3 Qlib：只借鉴“评分 -> Top-K -> 控制换手”

借鉴 Qlib 的信号评分、Top-K 有界选择、持有/替换阈值和按时间快照评估思想。不引入 `pyqlib` 依赖，不复制完整组合优化器。现有模拟账户已经有更贴近本项目的资金和风险约束，继续作为最终权威。

### 4.4 本仓库 AlphaSift：复用经验，不建立反向依赖

首版不允许 `MarketHotspotService -> AlphaSiftService` 反向耦合。可把其中通用的字段规范化、节流、重试反例迁移成数据层测试或中立帮助函数；不得复制一套新的裸 HTTP 实现后留下两份长期漂移代码。

## 5. 固定业务契约

### 5.1 运行时点

- 自动发现只消费已经持久化、确认属于当前 A 股交易日且包含完整收盘数据的大盘报告。
- 默认由 15:10 自动分析链路在大盘报告完成后触发，不依赖固定等待若干分钟。
- 非交易日跳过。
- 盘中大盘报告仍可用于风控和展示，但首版不用于自动扩张候选池。
- 新机会报告属于盘后报告，最早从下一交易时段进入开盘确认和监控。

### 5.2 大盘状态门禁

| 大盘状态 | 发现 | 自动 LLM 分析 | 新计划执行 |
| --- | --- | --- | --- |
| `normal` | 允许 | 允许 | 按现有完整门禁 |
| `cautious` | 允许，但提高阈值并缩小数量 | 允许 | 继续使用现有 0.50 仓位倍率 |
| `risk_off` | 记录阻断运行 | 禁止 | 禁止开仓/加仓 |
| `unavailable`/陈旧 | fail-closed | 禁止 | 禁止开仓/加仓 |

退出、止损、止盈、T+1 待平仓不受机会发现开关影响。

### 5.3 主题权威

- 主题只能来自结构化 `market_review_payload` / `market_theme_context`，不从 Markdown 正文正则猜测。
- 每个主题必须保留类型（行业/概念）、名称、代码（如有）、排名、涨跌幅、来源、抓取时间和数据质量。
- 行业与概念同名仍是不同身份，不能只用名称去重。
- 主题成分必须来自与主题类型匹配的接口；行业不能错误调用概念成分接口。

### 5.4 股票身份

- 内部统一为精确 `市场 + 交易所 + 代码` 身份。
- 裸 `512480` 不能跨交易所猜测等价；提供方代码必须先规范化并验证市场。
- 同一股票同时属于多个入选主题时只分析一次，但保留全部主题归因及一个确定的主主题。

### 5.5 机会生命周期

- 机会池与永久自选完全分离。
- 默认有效期为下一交易日结束；没有报告或计划的过期候选转为 `expired`，不删除。
- 新的更权威同日大盘报告可以取代尚未提交的旧机会任务；已保存的报告、计划、成交和持仓按现有最新报告及持仓规则处理，不删除历史。
- 所有状态变化必须可审计，禁止页面隐藏数据库仍活跃的任务。

## 6. 数据获取与过滤链

### 6.1 数据层公共接口

新增中立接口，语义类似：

```python
get_board_constituents(
    *,
    market="cn",
    board_type="concept" | "industry",
    board_name: str,
    board_code: str | None,
    as_of: date,
) -> BoardConstituentSnapshot
```

返回值必须包括来源、as-of 日期、抓取时间、字段映射版本、精确股票身份和原始数据质量。业务层不得直接依赖 AKShare DataFrame 中文列名。

### 6.2 硬过滤（任一失败即拒绝）

1. 非 A 股普通股票或身份不明确；首版不自动选择 ETF、可转债、北交所或其他市场。
2. ST、退市整理、已退市、明确停牌或不可交易。
3. 最近完整日 K 缺失、价格非正、日期不属于目标交易日。
4. 少于 60 根完整交易日 K 线，无法稳定计算趋势和波动。
5. 最近 20 日平均成交额低于配置阈值；默认建议 `1 亿元`，实施前用当前自选样本校准但不得在开发中静默降低。
6. 数据源字段冲突、重复代码指向不同交易所、同日行情冲突。
7. 一字涨停/一字跌停等明确无法合理模拟成交的状态。
8. 用户配置的精确股票黑名单或板块黑名单命中。

硬过滤的每条拒绝原因都要持久化并在 Web 展示。

### 6.3 主题评分 `theme-policy-v1`

分值仅用于排序，不直接产生交易动作：

| 因子 | 权重 | 证据 |
| --- | ---: | --- |
| 大盘结构排名与强度 | 25 | 结构化领先行业/概念榜单 |
| 板块宽度 | 25 | 成分股上涨占比、有效样本数 |
| 3/5 日持续性 | 25 | 板块历史完整日 K，不用未来数据 |
| 成交参与度 | 15 | 成分股成交额覆盖和放量比例 |
| 数据完整性 | 10 | 来源一致性、覆盖率、新鲜度 |

- `normal` 默认入选线 65 分。
- `cautious` 默认入选线 75 分。
- 任一关键因子不可用时不把缺失当 0 后继续交易；主题标记 `insufficient_data`。
- 权重、阈值和计算公式必须用策略版本冻结到运行记录。

### 6.4 股票评分 `candidate-policy-v1`

| 因子 | 权重 | 示例证据 |
| --- | ---: | --- |
| 主题确认 | 20 | 主主题排名、宽度、持续性 |
| 相对强度 | 20 | 5/10/20 日相对沪深 300，不用未来数据 |
| 趋势质量 | 20 | MA5/10/20/60 排列、斜率、价格偏离 |
| 量能与流动性 | 15 | 成交额、量比、20 日均量 |
| 价格结构 | 15 | 突破、回踩、距高点位置，不猜测盘口 |
| 风险调整 | 10 | ATR、波动、近期回撤；高风险扣分 |

- `normal` 默认候选线 70 分。
- `cautious` 默认候选线 78 分。
- 评分使用确定性 Decimal/有限浮点规则，非有限值必须拒绝。
- LLM 评分、首页情绪分和模型文本不得进入候选预筛分数。

### 6.5 限额与成本保护

- 默认最多 3 个主题，每主题最多 3 个候选，总候选最多 8 个。
- `cautious` 最多 2 个主题、总候选最多 4 个。
- 每日 LLM 调用预算默认 16 次。
- 实际配置模型数为 `M` 时，候选数上限进一步收敛为 `floor(16 / M)`，保证每个候选都由同一组配置模型公平分析；不能因为新增模型而静默漏掉某些模型。
- 同一 `交易日 + 大盘报告 + 股票 + 模型 + 策略版本` 只允许一个分析任务。
- 单模型失败独立记录，禁止跨模型 fallback 冒充该模型结果。

## 7. 持久化模型

新增表名在实现前可按仓库命名规范微调，但业务字段不得删减。

### 7.1 `market_opportunity_runs`

- 唯一 `run_key`；
- 来源大盘报告、交易日、市场、大盘状态及状态记录 ID；
- 模式、策略版本、完整配置快照；
- `pending/discovering/ready/analyzing/completed/blocked/failed`；
- 主题数、候选数、调用预算、开始/完成时间、错误和证据。

### 7.2 `market_opportunity_themes`

- 运行 ID、主题类型/名称/代码；
- 原始排名和行情；
- 分项得分、总分、数据质量；
- `selected/rejected/insufficient_data` 和原因；
- 成分数量、有效样本数量、来源快照。

### 7.3 `market_opportunity_candidates`

- 精确股票身份、名称、主主题及全部相关主题；
- 硬过滤结果、分项得分、总分、排名；
- `selected/rejected/duplicate/expired` 和原因；
- 行情 as-of、数据来源、快照哈希和有效期。

### 7.4 `market_opportunity_analysis_jobs`

- 候选、模型、幂等键、状态与认领租约；
- task/query ID、尝试次数、有限重试时间；
- 最终报告、DecisionSignal、模拟计划外键；
- `pending/claimed/submitted/completed/blocked/failed/expired`；
- 禁止无限重试和不确定提交后盲目重复调用 LLM。

## 8. 多模型分析与计划生成

1. 从模型注册表读取所有实际启用模型；空列表时运行阻断，不使用默认写死模型。
2. 当候选与当天自选分析重复时，合并分析目标，只运行一次，并让报告同时保留 `watchlist` 与 `market_opportunity` 来源。
3. 机会分析注入来源大盘报告、主题证据、候选分项指标和数据质量，但继续使用现有统一报告 Schema、持仓上下文和交易风格。
4. 自动机会分析默认不逐股发送飞书，避免 8 股票 × 多模型刷屏；发送一条发现/分析汇总。真正模拟成交仍按现有机制逐笔通知。
5. 报告保存后必须进入现有报告计划补偿，不新增平行计划生成器。
6. 只有持仓感知后的有效动作是 `buy/add`，且止损、目标、盈亏比、量价规则完整，才可能形成可执行计划。
7. `watch/avoid/hold/reduce/sell`、格式失败或不可执行报告保留审计，但空仓时不得生成错误入场。
8. 计划仍需通过最新报告接管、开盘确认、行情新鲜度、多因子、资金和账户硬风控；机会分数不能越权。

## 9. 调度和跨容器恢复

- 机会任务由“已完成的盘后大盘报告”驱动，不仅靠钟表时间。
- 15:10 任务顺序：生成/确认完整大盘报告 -> 保存大盘状态 -> 原自选分析目标与机会目标合并 -> 多模型分析 -> 报告计划补偿。
- 使用现有 scheduler heartbeat/共享数据库所有权；Web 与 analyse 双容器不得同时提交同一任务。
- 每个运行和分析任务必须用数据库原子认领、租约和确定性幂等键。
- 进程在盘后中途重启时，从持久任务继续；无法确认 LLM 是否已提交的任务进入恢复窗口，不能立刻重复扣费。
- 当天最新完整大盘报告比旧报告更新时，只取代尚未提交的旧机会任务；已成交持仓继续受持仓风险契约保护。

### 10.1 API

- `GET /api/v1/market-opportunities/runs`
- `GET /api/v1/market-opportunities/runs/{id}`
- `GET /api/v1/market-opportunities/themes`

列表接口必须服务端分页并返回 `total`，不能再次固定截断 500 条后让页面误显示总数。

### 10.2 Web“今日风口/机会池”页面

页面展示：

- 来源大盘报告、交易日、数据新鲜度、大盘状态和策略版本；
- 入选/拒绝主题及原因；
- 候选股票、精确市场身份、分项分数、硬过滤结果和有效期；
- 每个实际配置模型的分析状态、报告链接、DecisionSignal 和计划状态；
- “为什么没有计划”的机器可读原因；
- 历史运行和前瞻表现，不与永久自选混在一起。

页面时间统一显示中国时间，详情长区域采用固定最大高度、折叠和内部滚动。模型列动态读取配置。

## 11. 配置设计

只新增一项主模式，减少互相冲突的布尔开关：

```env
MARKET_OPPORTUNITY_MODE=off        # off | observe | paper
```

- `off`：不运行。
- `observe`：只发现和展示，不调用 LLM、不生成计划。
- `paper`：完成发现、多模型分析和现有模拟计划链路。

辅助上限配置：

```env
MARKET_OPPORTUNITY_MAX_THEMES=3
MARKET_OPPORTUNITY_MAX_CANDIDATES_PER_THEME=3
MARKET_OPPORTUNITY_MAX_TOTAL_CANDIDATES=8
MARKET_OPPORTUNITY_MAX_LLM_CALLS_PER_RUN=16
MARKET_OPPORTUNITY_MIN_20D_AVG_AMOUNT_CNY=100000000
MARKET_OPPORTUNITY_BLACKLIST=
```

模型名单不单独复制配置；默认读取模型注册表全部启用模型。新增配置必须进入 config registry、Settings Web、`.env.example`、中文专题文档、英文专题文档和 `docs/CHANGELOG.md`。

## 12. 评估与回测

### 12.1 三层指标必须分开

1. **主题发现层**：主题未来 1/3/5/10 根交易日的绝对与相对指数表现。
2. **候选选择层**：Top-N 命中率、平均超额收益、最大有利/不利波动、候选换手率。
3. **LLM/执行层**：报告转计划率、可执行率、模拟成交率、胜率、已实现/未实现盈亏、按模型和主题分组表现。

不能只看最终盈利后倒推“风口识别准确”，也不能用未成交报告冒充交易结果。

### 12.2 无前视和幸存者偏差

- 每次运行冻结当时的主题、成分、行情、评分和来源快照。
- 评估只读取 as-of 之后的交易日数据。
- 首版只对上线后积累的快照做前瞻评估。
- 如果未来需要历史研究，必须另建 point-in-time 板块成分数据集；不能用当前成分列表回填过去。

## 13. 分阶段实施顺序

### 阶段 A：数据契约和只读机会发现

- 实现板块成分公共接口、精确身份、缓存/节流和 fail-closed。
- 实现主题/候选评分、快照表和只读 API。
- 模式保持 `observe`；不调用 LLM，不影响模拟交易。

### 阶段 B：持久任务和多模型分析

- 实现机会分析任务、原子认领、预算和跨容器恢复。
- 与自选分析目标合并，所有配置模型独立调用且无 fallback。
- 证明报告正确保留机会来源和模型身份。

### 阶段 C：现有计划链路接通

- 只复用 `DecisionSignal` 和报告计划补偿。
- 验证买入、观望、格式失败、大盘阻断、账户阻断、重启和重复运行。
- 不新增第二套模拟交易引擎。

### 阶段 D：Web、评估和正式启用

- 完成机会池页面、分页、状态解释和配置入口。
- 完成前瞻评估和来源筛选。
- 先以 `observe` 在真实数据上运行至少 3 个交易日；人工核对身份、成分和筛选原因后再切 `paper`。

任何阶段未通过验收，不得为了演示跳过直接启用下一阶段。

## 14. 严格验收矩阵

### 14.1 必须通过的正向流程

- 真实 AKShare 主题成分调用返回精确 A 股身份，并记录来源和 as-of。
- 一个完整盘后大盘报告能生成持久运行、主题、候选和拒绝原因。
- 多个实际配置模型各自得到一个任务；模型数变化后页面和预算自动适配。
- 一个真实模型响应能够保存为历史报告并回写分析任务；报告若可执行，现有补偿能关联 DecisionSignal 和计划。
- scheduler 等价运行在重启后不重复提交、不重复生成计划。
- Web 用真实 API 数据展示报告/计划链接、总数、分页和中国时间。

### 14.2 必须 fail-closed 的反例

- 只有 Markdown、没有结构化主题。
- 盘中或陈旧的大盘报告被误当盘后完整报告。
- 概念接口返回行业数据，或代码交易所冲突。
- AKShare 超时、空数据、字段改名、非有限数值、重复冲突数据。
- `risk_off/unavailable` 仍试图调用 LLM 或生成新风险。
- 模型失败后由另一个模型 fallback 冒名完成。
- 同股票跨主题、跨自选、跨重启产生重复 LLM 调用或重复计划。
- 空仓报告给出持有/减仓时错误生成买入计划。
- 超过 LLM 预算、主题/候选上限或 API 分页 500 条后静默截断。
- 用当前成分回填过去并计算“历史准确率”。

### 14.3 验证命令和运行证据

- Python 改动：`python -m py_compile`、聚焦 pytest、`./scripts/ci_gate.sh`。
- Web：`npm ci`、`npm run lint`、`npm run build`、机会池页面测试。
- 真实数据只读 smoke：在线调用至少一个行业和一个概念成分接口。
- 临时 SQLite 端到端：大盘报告 -> 机会运行 -> 候选 -> 多模型任务 -> 报告 -> signal/plan。
- 真实配置模型的有界 smoke：每个配置模型最多一个候选、禁止通知、禁止真实订单；模型输出不保证必须买入，但必须被正确分类和持久化。
- 容器运行证据：调度心跳、原子 owner、一次实际盘后 reconciliation 结果。
- 独立审查者必须检查前视、身份、重复调用、预算、风险越权、分页和用户可见说明。

## 15. 启用、风险与回滚

### 15.1 启用条件

- 所有 P0/P1 要求均为 `ACCEPTED`。
- 机械验证和独立复核通过。
- `observe` 真实运行至少 3 个交易日且无身份错误、来源陈旧或批量重复。
- 用户确认将 `MARKET_OPPORTUNITY_MODE` 从 `observe` 切换为 `paper`。

### 15.2 回滚

- 设置 `MARKET_OPPORTUNITY_MODE=off`：停止未来发现和机会分析。
- 不删除运行、主题、候选、报告、计划或交易记录。
- 已经成交的模拟持仓继续由现有止损、止盈、T+1 和最新持仓报告保护。
- 已生成但尚未成交的机会计划可通过现有计划生命周期标记失效；不得直接删表或改历史。
- 回滚该功能代码不应影响自选分析、大盘报告、DecisionSignal、普通模拟交易和原回测。

## 16. 实施过程防跑偏规则

- 需求编号、默认阈值、状态机或验收条件改变时，必须先记录计划修订及用户可见影响。
- 实现者只能提交 `READY_FOR_REVIEW`，不能自行宣布完成。
- 独立验证者不得仅看实现者结论，必须检查真实 diff、日志、临时数据库和反例。
- mock/fixture 可以证明局部逻辑，但不能替代真实 AKShare、真实 API 页面或真实调度所有权证据。
- CI 全绿不能替代“没有前视、没有错配身份、没有重复扣费、没有绕过风险”的语义验收。
- 任何未完成项必须标记 partial/blocked，不得改写为“后续优化”后宣称完整上线。
