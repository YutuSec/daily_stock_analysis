# 大盘风口机会池

大盘风口机会池的目标，是把完整盘后大盘报告里的结构化风口主题，转换成可审计、有限额、可回滚的候选股票池。它不是永久自选，也不是买入信号；候选后续即使进入模型分析和模拟交易，也必须继续通过现有报告契约、开盘确认、行情新鲜度、资金分配、账户风控、T+1、止损止盈等规则。

## 当前交付状态

- 已提供 API 与 Web 展示入口，用于查看机会池运行、主题、候选、模型分析任务、拒绝原因、来源证据和无计划原因，并提供受模式门禁保护的“仅发现”和“候选分析”操作。
- 已提供配置开关与限额项，默认 `MARKET_OPPORTUNITY_MODE=off`；模式切换是共享数据库运行时配置，Web/API 保存后无需重启容器。
- `paper` 模式不能因为配置存在就视为正式启用；必须先在 `observe` 模式下完成至少 3 个交易日的真实观察验收。
- 策略 v3 使用同一可信来源的 CSRC 行业全量每日快照作为机会发现基线，冷启动阶段也会正式记录观察，不再因为历史天数不足而让机会池停在“未使用”状态。
- 本页面不提供加入永久自选、连接券商或真实交易按钮。

## 模式

```env
MARKET_OPPORTUNITY_MODE=off
```

`MARKET_OPPORTUNITY_MODE` 在 `.env` 中只作为首次启动或数据库运行时配置缺失时的默认值。通过机会池页面保存，或调用 `PUT /api/v1/market-opportunities/mode` 后，模式会写入 `runtime_settings` 并记录到 `runtime_setting_audit`；`stock-server` 和 `stock-analyzer` 下一次机会池状态查询/盘后任务会读取同一个数据库值，不需要重新创建容器。需要回退到 `.env` 默认值时，可调用 `DELETE /api/v1/market-opportunities/mode` 清除数据库覆盖值，审计历史会保留。若运行时数据库读取失败，系统不会回退到 `.env` 的 `paper` 或 `observe`，而是以 `mode_source=degraded`、`mode_degraded=true` 的 `off` 模式 fail-closed。

- `off`：不发现新机会，不提交候选分析；历史记录仍可读取。
- `observe`：只发现和展示候选证据，不调用 LLM、不生成模拟计划。
- `paper`：候选可以进入所有实际配置模型的独立分析，并复用现有模拟计划链路；运行时会强制检查 `MARKET_OPPORTUNITY_OBSERVE_GATE_DAYS`，默认需要完成 3 个交易日 observe gate。大盘为 `risk_off` 时，新候选只做研究专用分析，不进入模拟计划链路，见[红灯研究与次日复核](#红灯研究与次日复核)。

关闭该功能只会停止新的机会发现，不会删除历史，也不会中断已有模拟仓的保护性退出。

## 限额

```env
MARKET_OPPORTUNITY_BOARD_SOURCE=csrc_tencent
MARKET_OPPORTUNITY_DISCOVERY_MAX_THEMES=15
MARKET_OPPORTUNITY_MAX_OBSERVATION_CANDIDATES=30
MARKET_OPPORTUNITY_MAX_THEMES=3
MARKET_OPPORTUNITY_MAX_CANDIDATES_PER_THEME=3
MARKET_OPPORTUNITY_MAX_TOTAL_CANDIDATES=8
MARKET_OPPORTUNITY_MAX_LLM_CALLS_PER_RUN=16
MARKET_OPPORTUNITY_RESEARCH_DAILY_LLM_BUDGET=16
MARKET_OPPORTUNITY_OBSERVE_GATE_DAYS=3
MARKET_OPPORTUNITY_MIN_20D_AVG_AMOUNT_CNY=100000000
MARKET_OPPORTUNITY_BLACKLIST=
MARKET_OPPORTUNITY_STYLE=
MARKET_OPPORTUNITY_RUN_TIME=
```

`MARKET_OPPORTUNITY_STYLE` 是机会池专用交易风格（`short_swing` / `position` / `trend`）。留空时机会池沿用 `PAPER_TRADING_STYLE`，与模拟交易主账户一致。显式配置后，它同时驱动机会池筛选和由机会池触发的个股分析（候选分析、红灯研究及各自的次交易日复核）：候选在筛选时冻结当时的风格，后续分析的历史窗口、核心均线和持有周期都按冻结风格计算，即使之后改了配置也不会改写；机会池候选生成的模拟计划同样冻结该风格，止损几何和持有周期按此风格执行，模拟交易对该计划的同会话重分析也沿用计划冻结的风格。它不改变主账户基础风格 `PAPER_TRADING_STYLE`、自选股的分析与计划，也不改写现有持仓已冻结的风格。弱市里中线筛选较难时可设为 `short_swing`：历史充足度门槛从 180 根放宽到 80 根、趋势打分改用 MA5/10/20，让更多短线标的通过样本量与趋势门槛；行情转好后改回空或 `position` 即可。`PAPER_TRADING_STYLE_OVERRIDES` 的精确 `市场:代码` 覆盖仍优先于该基础风格。除直接编辑 `.env` 外，机会池页「设置与说明」（默认折叠）里的「筛选风格（中/短/长）」下拉可直接切换该键，经 `PUT /api/v1/system/config` 带版本乐观锁保存并自动重载，下一次机会池运行即生效、无需重启。

`MARKET_OPPORTUNITY_RUN_TIME` 控制机会池在定时任务里的运行时间（北京时间 `HH:MM`，24 小时制）。留空（默认）时保持原行为：定时分析批次结束后立即运行机会池。A 股刚收盘时，部分数据源的当日日线往往还没有更新完整，候选会因缺少当日 K 线被大量拒绝，此时可设为 `20:00` 之类的晚间时间（建议 19:00–23:00，不要晚于 23:30）。设置后：

- 定时分析批次不再内联运行机会池，日志会输出“大盘风口机会池改为晚间运行”；
- 后台任务 `market_opportunity_evening_run` 在北京时间 15:00–23:59 之间每 5 分钟检查一次，到设定时间后每个 A 股交易日运行一次，内容与原先批次后运行的机会池流程相同，开始时日志输出“大盘风口机会池晚间运行开始”；
- 运行前必须已有当日交易会话的大盘复盘，且没有分析批次正在运行；不满足时本次跳过，5 分钟后再检查，不消耗当天的运行机会；休市日、交易日历不可确认、机会池为 `off` 或大盘复盘区域不含 A 股时同样跳过。跳过原因记录在调度器心跳中该后台任务的 `last_skip_reason`（如 `before_run_time`、`market_review_not_ready`、`analysis_busy`、`trading_calendar_unavailable`）；
- 每个交易日在所有调度实例之间只运行一次：Docker 部署里 server 的运行时调度器和 analyzer 的 CLI 调度器都会注册该任务，开始前先在数据库领取当日的会话租约（调度器心跳中的任务名 `market_opportunity_evening_session`），没领到的实例记 `session_claimed_by_other_instance` 跳过；数据库暂时不可用时记 `session_claim_unavailable`，不运行、也不消耗当天的机会，5 分钟后再试；
- 运行失败当晚不自动重试，其他实例也不会接着重跑（与原先批次后内联运行的语义一致）；正常结束或失败后重启进程也不会再跑。只有运行中的实例崩溃或被重建、来不及收尾时，租约在 3 小时后过期，届时其他实例可以接手，同一大盘报告的机会池批次按幂等键复用，不会重复创建任务；
- 晚间运行期间不持有分析批次锁：分析批次不会因此被跳过，但若定时分析时间设在晚间运行时段内，两者可能同时进行；
- 格式无效（如 `8:00`、`24:00`、`20:30:00`）时按留空处理并记录告警。

该键与 `MARKET_OPPORTUNITY_STYLE` 一样可在 Web 设置页修改，下一次检查时自动读取，无需重启。

`MARKET_OPPORTUNITY_BOARD_SOURCE` 指定每日板块观察来源，当前实现默认 `csrc_tencent`，只接受同源、同分类、同交易日、完整身份的快照。`MARKET_OPPORTUNITY_DISCOVERY_MAX_THEMES=15` 是从板块快照进入发现阶段的主题上限；`MARKET_OPPORTUNITY_MAX_OBSERVATION_CANDIDATES=30` 是观察池可保留的候选证据上限。它们与分析预算分离：进入模型分析仍受 `MARKET_OPPORTUNITY_MAX_THEMES=3`、`MARKET_OPPORTUNITY_MAX_TOTAL_CANDIDATES=8` 和 `MARKET_OPPORTUNITY_MAX_LLM_CALLS_PER_RUN=16` 约束。

`MARKET_OPPORTUNITY_RESEARCH_DAILY_LLM_BUDGET=16` 是红灯研究每个市场、每个交易日的模型调用总上限，首次研究、次日复核和每次重试共用；实际生效值取它与 `MARKET_OPPORTUNITY_MAX_LLM_CALLS_PER_RUN` 中更小者。设为 `0` 会停止全部研究调用，不影响板块快照和观察证据采集；不配置时按 16 运行。

模型列表不在机会池里单独配置，运行时读取系统实际启用模型。候选预算会随模型数收缩，避免新增模型后只分析部分模型。候选列表的模型筛选仅选择展示哪个模型的任务与无计划原因；尚未创建该模型任务的候选仍保留，显示 `missing / job_not_created`。分页总数按候选计，不按任务行数计，其他模型任务不会混入当前筛选。

## 策略 v3 观察框架与 v4 评分修正

机会池现在先把每个已收盘交易日的可用 CSRC 行业排名完整冻结为 `BoardObservation` 快照，再从同一来源中选出最多 15 个主题进入机会发现。快照保存独立于 LLM 报告是否成功、是否 `risk_off`、以及当天最终是否有候选；只要同源全量快照真实可用，就能成为后续观察证据。`theme_key` 仍保留 `industry:名称` 这样的可读语义，但跨日匹配会同时校验 `theme_code`、`theme_source`、`theme_taxonomy` 和 `as_of`，避免把同名不同源或代码变化的板块混为同一条历史。

冷启动不再拒绝观察。历史不足时，主题和股票可以进入观察池，保留缺失日期、来源、窗口大小和拒绝原因；板块历史成熟度只参与评分和证据展示；股票与基准日线、流动性等必要数据完整且达到评分/形态要求时，可以进入分析候选。实际调用模型仍须通过全局 3 个健康交易日门槛，不要求每个新板块另攒满 5 日历史。健康的零候选运行可以计入 3 日工程观察门槛，因为它证明“系统完成了真实发现并得出零候选”；数据源失败、日历不可信、未收盘、未来日期、缺失真实交易日或只剩 name-only 旧记录的情况都不能补作健康日。

`risk_off` 阻断计划生成和模拟入场，但不再一概阻断模型分析：`paper` 模式且观察门槛已完成时，红灯日的新候选只做研究专用分析，报告不生成 DecisionSignal、模拟计划或主账户确认；`observe` 模式仍只采集、不调用模型；大盘状态为 `unavailable`（所需数据不可用）时仍阻断全部新分析。系统照常采集和展示观察证据。`observe` 与 `paper` 的差异仍然保留，`paper` 也必须继续满足观察门槛、预算和执行层风控。

旧历史不会被重新贴上新来源。已冻结的历史快照用于审计和同样本对照；缺少真实全量快照的交易日只能显示为缺口，不能用当前数据重构过去，也不能把旧 name-only 报告补成 `csrc_tencent` 健康日。

### 20 日强弱实际进入排序

`opportunity-policy-v4` / `theme-policy-v4` 修复了原先只保存 `return_20d`、没有消费它的缺口。`board-discovery-v2` 的发现分为：当日排名（0–30）+ 当日涨幅强度（0–20）+ 近 5 日持续性（0–20）+ 5 日复合涨跌幅（截断到 −10 至 10）+ 20 日复合涨跌幅（截断到 −20 至 20）。收益数值均为百分点，例如 `5` 表示 5%。完整负收益会扣分。

最终主题评分还会将 20 日分量乘以 0.5（最多加减 10 分），加到原当日排名强度后截断到 0–20；其余宽度、流动性、完整性及持续性权重不变，总分仍为 0–100。这样 20 日强弱既影响哪些板块进入发现预算，也影响最终主题排序和股票归属主题，不会在二次评分时丢失。

20 日窗口必须使用截至信号日的连续 20 个真实交易日、同来源/分类/代码的完整每日快照。缺任一天或有效涨跌幅时，收益为 `null`，贡献为 0，同时保留 `return_20d_evidence` 的状态、可用数量和缺失日期；这不同于完整负收益，也不是新的硬性等候期。API 的主题 `score_components` 返回发现分解、20 日证据与最终调整分。`evidence_stage` 仍表示 5 日短窗状态，20 日完整度以 `return_20d_evidence.status` 为准。运行键包含新策略版本，旧批次继续冻结；历史成分回放仍不增加健康观察日。

这些权重属于待检验参数，研究中的动量规律不等于对本系统收益的证明。验收应同时核对候选后续相对收益、实际成交率、扣费后的模拟收益与回撤；不能以候选更多、观望更少或价格触及理论买点作为盈利证据。`watch` 报告即使列有参考买点，也必须由报告明确授权条件入场后才能进入对应执行链路。

### 健康观察日与候选数据质量分开

`board-observation-health-v2` 使用已持久化的完整板块快照作为观察日真源，按交易日去重，独立于报告生成和个股筛选。核验同市场、同来源、同分类、主题身份与数量、快照哈希、可信交易日和真实收盘后采集时间；无完整快照、盘前/盘中、周末、未来日期、错误身份及历史成分回放均不能凭运行次数补出观察日。已有真实快照可以只读重新核验，不用重新抓取过去的板块数据。

单只或多只候选缺行情、候选全部被拒绝、板块历史尚短以及 `risk_off` 都不抹掉已经成功采集的板块观察。候选缺数据仍按原规则拒绝，`risk_off` 仍阻断新入场（`paper` 模式下只允许研究专用分析），模拟模式仍要求 3 个真实健康交易日，且不会自动切换模式。

`observe_gate.counting_basis` 返回 `healthy_board_observation_days`；原有 `completed_trading_days`、`healthy_run_days` 和 `dates` 保留兼容，含义为健康快照交易日。运行 API 的 `provenance.observation_health` 是按当前口径只读投影的健康判定，原始判定保留在 `recorded_observation_health`，不更新冻结数据库行。候选问题另列在 `observation_health.discovery_quality`，包括候选/主题不完整计数；`scope=discovery_candidates` 表示当次完整检查范围，`persisted_candidates` 表示旧批次保留下来的候选记录范围，不能把后者当作曾检查过的全市场样本数。

## API

所有接口位于 `/api/v1/market-opportunities`，复用管理员会话认证：

- `GET /status`：返回模式、来源、版本、降级标记、实际配置模型、限额和 observe gate 状态；其中 `observe_gate.dates` 是已计入门禁的观察交易日，Web 会直接展示这些日期。
- `GET /runs?page=&limit=`：分页返回机会池运行，包含 `total`。
- `GET /runs/{id}`：返回单次运行详情、主题、候选和模型任务，并附带 `llm_submitted_job_count`（本次真正提交到 LLM 的分析任务数，失败在提交前的任务不计入）。
- `GET /themes?page=&limit=`：分页返回主题证据。
- `GET /candidates?page=&limit=`：分页返回候选股票、动态模型状态和无计划原因。候选的 `model_states` 每项附带 `execution_intent`（`paper_candidate` / `research_only`）、`research`（`kind` / `outcome` / `review` / `review_of`）以及报告的 `action` / `action_label`，用于在页面上区分“生成模拟计划”和“只做研究”。
- `GET /analysis-jobs?page=&limit=`：分页返回模型分析任务。
- `GET /evaluation?run_id=&windows=10,20,40`：只读返回前瞻评估，窗口只使用候选 as-of 之后的 K 线。10/20/40 日窗口用于观察策略口径，不代表已验证收益。
- `POST /discover`：只从最新或指定大盘报告发现候选，不调用 LLM；`off` 模式拒绝执行。
- `POST /runs/{id}/analyze`：只分析指定 run 的候选，并受 `paper` 模式、observe gate、实际配置模型和 `MARKET_OPPORTUNITY_MAX_LLM_CALLS_PER_RUN` 限制保护。红灯批次只为尚未建任务的入选候选创建研究专用任务，并受研究每日预算约束，预算不足时返回 `blocked` 和对应研究阻断原因；研究复核批次不新增任务，只继续处理已物化的复核任务；红灯下的主账户两日确认复核批次和大盘状态 `unavailable` 的批次仍返回 `blocked`。

列表接口都必须使用服务端分页和 `total`，不得在前端静默截断 500 条后冒充总数。

运行时模式接口位于 `/api/v1/market-opportunities/mode`：

- `GET`：返回当前有效模式、来源、版本号和更新时间。
- `PUT`：提交 `mode` 和必填 `expected_version`，使用乐观锁防止覆盖别人刚切换的模式；写入成功后追加审计日志，不改写 `.env`。当提交 `paper` 但 observe gate 未完成时返回 `409 observe_gate_incomplete`，不会先写入覆盖值。无数据库覆盖值且从未变更时，状态接口返回 `mode_version=0`；如果曾经设置后又清除，则返回该 key 的最新审计版本，下一次写入必须提交这个版本号。
- `DELETE`：按必填 `expected_version` 清除数据库覆盖值，使系统重新使用 `.env` 默认值；清除动作同样保留审计。

## Web 页面

入口：`/market-opportunities`，侧边栏显示为“机会池”。页面按“先结论、后证据”的顺序展示：

- 顶部运行概览：交易日、运行编号、运行状态、起止时间（UTC+8）、运行模式、当日大盘状态及其后果（风险偏高时显示“只做研究，不生成模拟计划”）、数据完整度，以及 LLM 实际调用次数 / 上限（`llm_submitted_job_count` 与 `limits.max_llm_calls_per_run`）和下一次运行时间（读取 `MARKET_OPPORTUNITY_RUN_TIME`，未配置时显示“随定时分析批次”）。
- “送 LLM 分析的 N 只”结论表：只列出确实创建过分析任务的候选，列为股票、主题、规则分、LLM 建议（含是否看多）、结果和下一步；看多的候选排在前面，点开某一行展开原有的执行评估证据、缺失证据、新旧策略对照和各模型明细（任务状态、报告 ID、Signal ID、模拟计划 ID、执行意图与研究结论）。“计划已生成，但不可执行”与“没有计划”分开显示，并给出两日确认进度和精确的无计划原因。红灯下的研究任务在结果列显示为“仅研究”。
- “待复核 / 待确认”队列：汇总研究复核和两日确认义务，按到期日排序，显示到期日、进度和派生运行编号。
- 前瞻评估：保留 10/20/40 交易日窗口、模型转报告/计划转化和已实现模拟盈亏摘要；未确认真实成交的结果会标为 proxy，不与真实成交盈亏混写。研究任务在评估中单独计为 `research_jobs` / `research_reports`，不计入模型转报告/转计划比例。
- 其余未送 LLM 分析的候选默认折叠，标题给出“其余 N 只（观察 N · 淘汰 M）”和各类中文原因计数，达标但尚未分析的候选另计“达标未分析”；展开后可查看候选详情并做分页与状态筛选。
- “设置与说明”默认折叠，集中放置模式切换、筛选风格、晚间运行时间、观察验收规则、限额、字段解释、`provenance` 和运行诊断。观察门禁显示后端 `observe_gate.dates` 返回的已计入日期，字段存在但数组为空时明确显示“尚无计入观察门禁的日期”；运行诊断中数据源不可用/大盘主题缺失显示为阻塞，不与真实筛选后零候选混为一谈，红灯批次的 `risk_blocked` 表示阻断模拟执行，不代表没有研究任务。后端返回的英文短原因（含 `candidate_rejected: a, b` 这类组合原因）和运行状态都会逐段翻译成中文，模式的英文 `message` 不再直接渲染。

时间统一按中国时区显示为 `UTC+8`。页面只有两层折叠（结论表行、其余候选与设置区），不再使用卡片内部滚动套滚动。

## 与自选和模拟交易的关系

机会池候选不会自动写入 `STOCK_LIST` 或 Web 永久自选。即便某个候选被模型分析为买入，也只是在满足全部现有模拟交易门禁后，才可能生成模拟计划；红灯研究报告即使看多也不会生成模拟计划。机会分数只用于排序和审计，不能越过执行层风险控制。

候选在调用 LLM 前会以只读 `selection_context` 注入板块、排名、评分分项、行情来源、快照日期及数据质量。提示词明确要求模型独立复核，证据不足时输出观望/回避，不能把“入选机会池”直接当作买入指令。同一天的普通人工报告即使股票、模型和日期相同，只要没有同一候选键的机会池证据，就不会被复用为机会池任务结果。

候选评分会先对全部合格股票统一排序，再应用每主题和总候选上限，避免前一个板块的成分顺序挤掉后续更高分股票。技术窗口读取机会池生效交易风格：默认沿用 `PAPER_TRADING_STYLE`；配置了 `MARKET_OPPORTUNITY_STYLE` 时改用它作为机会池基础风格，并冻结到候选，供后续个股分析和机会池模拟计划使用，不改变主账户基础风格、自选股计划和现有持仓（`PAPER_TRADING_STYLE_OVERRIDES` 的精确 `市场:代码` 覆盖仍然优先）。例如中线持仓会纳入其核心均线窗口，而不是固定套用短线窗口。评分仍只负责筛选，最终动作必须由完整个股分析和执行层风控决定。

## 日期、重试与两日确认

手动分析旧批次也必须用当前可信交易日校验，不能用批次自己的日期证明有效。交易日历不可确认时禁止新提交；盘后调度先全局恢复已提交任务，再执行新的机会发现。恢复时先找已保存的报告：过期报告只关联审计结果，不补建当前计划；无报告且跨日的任务关闭。当天未知状态超过原有 900 秒领取窗口后标记失败，不自动重发未知是否仍在执行的 LLM 请求；已明确返回失败的同步调用才进入现有有次数上限的重试流程。

同日报告复用要求非空快照指纹、选股契约版本及完整选股证据一致（主题、分数分项、行情快照、日期等）；不能仅凭同股票或同哈希复用。批次/任务 ID 不属于分析证据，可以不同。被复用报告首次保存时冻结的执行用途和范围也必须与当前任务一致（现有机会池执行任务为 `paper_candidate/primary`），研究专用报告不会被复用为可执行任务结果，复用也不会改写原报告用途。新分析会在首次保存时写入 `paper_candidate/primary` 与候选快照日期；详细授权规则见[模拟交易文档](paper-trading.md)。

候选技术评分使用现有风格配置：短线波段读取 80 根历史、MA5/10/20 与 20 日收益/波动；中线持仓读取 180 根、MA10/20/60 与 60 日收益/波动；趋势持有读取 500 根、MA20/60/120/250、250 日收益与 120 日波动。相对基准收益换算到统一 20 日刻度后评分，不因观察期更长自动加分。短线价格结构仅是择时分项；缺少风格要求的历史不得通过候选筛选。这是筛选口径对齐，并不代表已经验证选股收益提升。

- 股票、基准、板块快照、候选 `as_of` 和机会池 run 必须精确对齐同一目标交易日。仅仅 `valid_until` 尚未到期，不代表旧 run 可以在新交易日提交或领取任务。
- 数据源失败、主题缺失或全部板块成分不可用时，run 标为 `blocked` 并保留原因；该批次在没有任务进入已提交/完成状态前可以使用相同幂等键重新发现。真实完成筛选但没有股票达标时才是健康的零候选终态。
- 观察门槛按真实交易日和真实快照计数。缺失交易日不能跳过后补为健康日；完整执行且零候选的健康快照可以计入 3 日工程门槛，但不说明策略收益有效。
- 首日完整分析若只达到入场确认 `1/2`，系统会在首日 job 上持久记录一次次交易日复核义务。次交易日必须重新获取完整数据并再次调用同一个模型，不会只复用首日报告，也不会加入永久自选。
- 复核 run/job 使用确定性键，调度重试不会重复创建。只有在指定次交易日可以执行；错过后标记 `expired`，不得在更晚日期补跑陈旧信号。复核未确认、生成观望/回避或计划仍不可执行时，旧入场继续冻结；已有持仓的止损、止盈与 T+1 保护不受影响。
- 定时单模型或多模型运行中，即使模型失败，机会池补偿与模拟交易保护账本仍分别尝试执行；失败汇总后上报，不会因第一个辅助任务失败而跳过第二个。配置 `MARKET_OPPORTUNITY_RUN_TIME` 后，批次内只执行模拟交易保护账本，机会池改由晚间后台任务运行，见[限额](#限额)中的说明。

## 红灯研究与次日复核

- 准入：同时满足 `paper` 模式、观察门槛已完成、当日大盘状态为 `risk_off`、存在实际配置模型、研究预算足以覆盖整组模型时，红灯日的入选候选会按全部配置模型创建研究专用任务。`observe` 模式不调用模型；大盘状态为 `unavailable`（所需数据不可用）时不创建研究，已到期的研究复核也以 `market_regime_unavailable` 结束。
- 权限：研究报告在首次保存时冻结为 `research_only/primary`，不注入真实或模拟持仓上下文，不生成 DecisionSignal、模拟计划、thesis，也不计入主账户两日确认；任务证据中的对账结果固定为 `execution_not_authorized/research_only`。判定以报告自身动作为准，不做评分对齐：只有买入/加仓算看多，其余动作（观望、持有、减仓、卖出、回避、预警）和无法识别的动作都算非看多，程序不会把观望改成买入。研究记录冻结报告 ID、模型、提示词指纹、输入与输出哈希、候选身份和报告给出的条件点位，只包含与账户无关的事实。
- 次日复核：首次研究看多时，会在下一个真实交易日预留一个研究预算名额并记录复核义务。到期日重新取数、用同一模型重新完整分析，结果仍是研究专用，不形成主账户确认，也不会再派生下一次复核。复核只能在到期当天执行，错过后标记 `expired`，不会在更晚日期补跑或补确认；到期日名额已满时复核记为 `skipped`（`research_review_budget_unavailable`）。
- 预算：每个市场、每个交易日的研究调用共享一份预算，复核优先：复核名额在前一交易日已预留，新候选只能使用剩余名额，并且准入时按整组配置模型计算，不会只为部分模型建任务。每次提交模型调用（含重试）占用一个名额，名额不释放；同一次尝试在重启后不会重复计费。调用时以预算账本为硬上限，重试用尽名额后，剩余研究任务以 `research_budget_exhausted` 结束。研究准入状态写入 run 的 `provenance.research`，阻断原因为 `configured_models_missing`、`research_budget_zero`、`research_budget_insufficient_for_configured_models` 或 `research_budget_exhausted`；没有入选候选时不报告预算阻断。
- 复用与重启：同一股票、同一模型、同一交易日的研究专用报告只生成一次，首次研究与复核互相复用，但不会复用为可执行任务结果。复核日重新发现同一股票时，新的首次研究会复用当日报告，并按新信号日另排复核，后续消费方应按报告 ID 去重。已提交但重启后找不到报告的研究任务，在原有 900 秒领取窗口内视为状态不确定，不会重发调用，超时后才终态失败。跨日才找回的研究报告只留档，不排复核，也不补完成复核。
- 结果区分：盘后调度结果新增 `research_outcomes`，统计本轮发现批次和到期复核批次中研究任务的 `bullish`（看多）、`non_bullish`（观望等非看多）、`analysis_failed`（分析失败）、`budget_exhausted`（预算用尽）、`data_unavailable`（所需数据不可用）、`expired`（错过会话）和 `in_progress`（尚未结束）。板块或成分数据源失败仍表现为批次 `blocked` 及 `market_themes_missing`、`theme_constituents_unavailable` 等原因；真实零候选是 `selected_candidate_count=0` 且没有阻断原因。定时任务日志“大盘风口机会池完成”会同时输出 `research_block` 与 `research_outcomes`。

## 自动任务与预算边界

- 合格板块先按分数排序，再按用户上限与行情上限中更小的值入选；超额板块保留拒绝原因，不显示为入选。平分时按来源排名、板块键稳定排序。
- 观察宽度和分析宽度独立：每日最多 15 个主题进入发现、最多 30 个候选保留观察证据；只有最多 3 个主题、8 个候选进入分析预算，单 run 最多 16 次模型调用；红灯研究另受每日共享研究预算约束。
- `MARKET_OPPORTUNITY_MAX_LLM_CALLS_PER_RUN=0` 让新建批次的模型调用预算保持为零，由于研究预算取两者更小值，红灯研究也不会调用模型。已有合格候选但预算不足以覆盖全部配置模型时，批次明确阻塞，不显示空任务“完成”，也不会偷偷只调用部分模型；已冻结的批次预算不因本次修复被追溯重写。
- 自动入口在休市或日历不可信时不新增发现、不生成复核任务、不领取新的模型任务；已提交任务仍可按原有恢复规则收尾。人工研究入口不因此一律禁止，但仍受模式、日期和预算等原有规则约束。
- 当市场进入 `risk_off` 时，自动入口仍做板块快照和观察证据采集；`paper` 模式下只推进研究专用分析和到期研究复核，不推进主账户候选分析、主账户两日确认、报告转计划或模拟入场。
- 这些修复不会自动从 `observe` 切换至 `paper`，也不会降低观察验收门槛。

## 板块数据源与观察门槛

行业排行优先使用 Eastmoney/BK；失败后使用独立的 `csrc_tencent` 备用链路：BaoStock 提供当前证监会行业分类，腾讯提供带交易日期的批量报价，按同一组成员的涨跌幅等权计算排行。该统计不是官方行业指数，报告和模型输入会明确说明口径。新排行不再使用存在旧分类错配的新浪行业目录。

新源的行业代码为 `csrc_C27` 等，排行、成分、日期和来源身份贯穿报告与机会池；不能与相似名称的 Eastmoney、申万或新浪行业混用。只有成员报价完整且满足日期/时效约束的行业可以进入排行；不会通过删掉报价缺失的成员来抬高行业表现。保留现有至少 5 个成员、行业持续性、流动性、观察验收和交易风控门槛。

机会池在请求行业成分前校验排行来源与代码配对；缺少身份、代码与来源冲突的行业保留为 `source_identity_unavailable`，不会按名称跨来源补齐成分。这也适用于外层数据源降级后只返回行业名称的结果；大盘文字展示可保留，但不能据此选股。概念主题沿用原有独立规则。

分类读取使用独立进程：单页最多 10,000 行（满页拒绝，防止静默截断），校验字段与游标消费完整性，最多 60 秒；全量快照最多 120 秒。真实全量分类查询约需 40–52 秒，因此首次冷启动会比缓存命中慢。进程内共享缓存与单次构建锁减少重复拉取；失败有 30 秒冷却，不使用过期的跨日成功快照。缓存不能绕过盘中报价的新鲜度检查。

报价批次共用一个 HTTP 会话；连接异常或读取超时最多重试一次，仍受总预算约束。403、429 等明确拒绝不重试；重试失败不会保存部分成功快照。

历史 `hangye_*` / `gn_*` 报告仍由原来源适配器处理；已知 `BK...` 身份不会被按名称偷换。旧新浪行业成员必须通过独立 CSRC 核验（包含编码前缀解析），任何冲突、缺失、未来或超过 31 天的分类都不能通过选股门槛。保留 `akshare_sina` 作为历史账本来源标识，不代表当前传输使用 AKShare。

新派生行业只积累同来源的真实观察，不借用同名 Eastmoney 历史、不回填虚构日期。数据源恢复后，若仍缺少既定行业观察窗口，候选会继续等待；这与“接口失败”是不同状态。只有满足现有观察门槛后才允许进入模型分析/模拟计划链路，恢复数据源不等于自动产生买入计划。

主题持续性不能由 LLM 大盘报告里的“持续 N 天”文字直接证明。可执行筛选优先使用同源板块历史 K 线；新浪成分不能混用同名 Eastmoney 板块历史。当备用源只有当日成分时，系统会使用本地同源机会池历史做固定窗口观察：当前交易日 + 前 4 个真实交易日的健康同源快照。完整 5 日窗口中至少 3 天为正可标记为确认；完整但上涨天数不足会标记为成熟的负向/未确认窗口，而不是冷启动。5 日或 20 日收益只有在窗口完整且每日收益有限时才返回；缺日、代码变化、来源不一致或旧 name-only 记录都会使对应窗口保持缺口。修复数据源后仍可能暂时没有候选，这是积累可验证历史，不是继续调用失败；失败运行不计入有效观察。

## 历史冻结与前瞻评估

历史快照是审计证据，不是可重算数据集。已冻结的老样本可以用于同样本旧新对照，例如比较 v2/v3 在相同候选 as-of 下的入选数、拒绝原因、转报告/转计划比例和后续 10/20/40 日价格表现；但缺失日不能用当前接口补写，旧记录也不能因为名称相同就升级为 `csrc_tencent` 健康快照。旧新对照必须标明哪些样本有完整同源证据，哪些只能作为历史账本保留。

前瞻评估默认区分两类结果：已有模拟计划且有执行账本的，展示真实计划和成交相关结果；没有成交确认、仅能用候选 as-of 之后行情估算的，标为 proxy。proxy 可用于观察筛选口径是否过紧、是否错过明显主题，但不能当作真实交易收益，也不能据此声称策略已被验证。

前瞻评估只读取已持久化的 `StockDaily`。观察候选没有进入 LLM 时，发现阶段拿到的 daily bars 不会天然留到未来窗口；因此策略 v3 增加独立的历史刷新闭环：每天收盘后按最近 120 自然日内的 `selected`、`observing` 以及 `score_components.strategy_comparison.legacy_selected` 候选去重 symbol，从最早候选 `as_of` 起跟踪其后 40 个真实交易日内尚未落库的日线，并保存沪深 300 基准为 `000300.SH`。刷新只补行情，不补报告、不捏造成交；单个 symbol 失败会写入 summary，其他 symbol 继续处理。过期日期、未来日期、盘中和非真实交易日不会触发 fetch。后补 K 线会保留 `data_source`，但仍需把价格口径视为数据源口径；若数据源后续调整复权或历史价格，旧新对照必须说明这一限制。

## 回滚

将模式设为：

```http
PUT /api/v1/market-opportunities/mode
{"mode":"off","expected_version": 当前状态返回的 mode_version}
```

保存后下一次机会池任务会自动停止新的机会发现，无需重启服务。不要删除机会池历史表或手工修改运行库；它们是后续观察验收和前瞻评估的证据。若需要完全回到启动默认值，请调用 `DELETE /api/v1/market-opportunities/mode` 并携带当前 `mode_version`，由受审计接口清除覆盖值后再让 `.env` 默认值接管。

只需停止红灯研究时，设置 `MARKET_OPPORTUNITY_RESEARCH_DAILY_LLM_BUDGET=0`，或把模式切回 `observe`/`off`，无需回退代码；已生成的研究报告、研究预算账本和复核记录保留供审计。若必须回退到不识别研究任务的旧版本，应先完成上述设置，回退后也不要对红灯批次或研究复核批次手动调用 `POST /runs/{id}/analyze`：旧版本不识别研究任务键，可能把尚未完成的研究复核任务当作普通候选任务处理。报告执行用途表的回退限制见[模拟交易文档](paper-trading.md)。

## 回放与数据完整性

指定旧报告再次发现时，可以复用该报告同市场、同日、同来源与代码的已冻结成分；运行标记 `frozen_membership_replay`，不将这种局部历史回放计为全量健康观察日。后补日线严格截止信号日，旧/新选择共同使用同一成分样本。缺少原始来源身份的旧报告仍拒绝补造。

沪深 300 使用显式指数日线接口，保留 `sh000300` 身份，不按裸股票代码猜测市场。股票筛选要求最近 20 行成交额有效；若某源只有 OHLCV 而没有成交额，则继续尝试后续源，不用量乘价估算成交额。必要数据仍缺失时拒绝该候选，JSON 中缺失数值保存为 null。

前瞻窗口按真实交易日对齐，缺失中间交易日不能用更晚 K 线顶替。次日开盘代理的 1 日退出受 A 股 T+1 限制，不提供可执行同日收益；代理超额收益与基准使用相同起止日和开盘基准。实际模拟盈亏按成交/仓位账本净值统计，不重复扣费。同日同股票重复运行的评估以最新批次去重。

真实截至当日且价格日期有效、但不足策略最低长度的短历史仍拒绝入选，作为正常的资格不足保留（例如新上市股票），不会单独使整日观察不健康；没有日线、过期数据或非有限值仍按数据失败处理。

候选分页优先显示最新批次中排名靠前的入选与观察记录，再显示拒绝审计记录。页面观察候选数读取 `provenance.observation_candidate_count`，可分析数读取批次顶层 `selected_candidate_count`；顶层 `candidate_count` 包含拒绝记录，不作为观察池数量。
